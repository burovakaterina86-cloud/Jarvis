# Агент «Контент-план 2.0» — полная инструкция

Версия 1.0 · 15.09.2026

Агент раз в неделю собирает контент-план для Instagram, YouTube и Telegram. Все темы берутся из того, что реально залетело за последние 14 дней на выбранном рынке (по умолчанию англоязычном). План выдаётся красивой HTML-страницей, Word-документом и письмом на почту.

Инструкция универсальная: подходит маркетологу, психологу, коучу, врачу, астрологу, магазину. Всё, что зависит от человека и ниши, помечено ✏️ и заполняется при первом запуске.

---

## Как пользоваться этим файлом

**Первый запуск** — по отдельному файлу `1-ПЕРВЫЙ-ЗАПУСК.md`: там вопросы, разбор присланных рилсов, облако тегов, пробная выдача 15 рилсов и таблица «что переписать». Итог первого запуска — личная копия этой инструкции в `клиенты\<имя>\ИНСТРУКЦИЯ.md`, дальше агент работает по ней.

**Еженедельный запуск:** «Сделай контент-план на неделю с понедельника ДД.ММ по моей инструкции `клиенты\<имя>\ИНСТРУКЦИЯ.md`».

## 2б. Режимы работы

Экономим на оформлении, а не на контенте. Сбор, расшифровки, отбор по тексту и стратегия одинаковы в обоих режимах: качество плана от режима не зависит.

| | Полный | Эконом |
|---|---|---|
| Сбор, расшифровки, отбор | полный | такой же |
| Перевод сценариев | все 15 целиком | рекомендуемые 5 целиком, остальные хук и пересказ в 3–5 фраз (полный текст по запросу «разверни рилс N») |
| HTML-страница | генератор плюс доводка дизайна и проверка скриншотами | тот же генератор, без доводки и скриншотов |
| Word | да | нет, только по запросу |
| Письмо | свёрстанное, с вложениями | нет, по запросу простое текстовое |
| Субагенты | 8 | 5: сбор, отбор, перевод и раскладка, карусели вместе с YouTube, стратег вместе с оформлением |
| Отчёты субагентов | подробные | 5–7 строк |
| Токены | ≈ 1,5–2,2 млн | ≈ 0,5–0,8 млн |
| Apify | ≈ $4,5–6 | столько же |

Режим переключается в любую неделю: «сделай план в экономном режиме».

**Чего в эконом-режиме делать нельзя:** сокращать сбор, пропускать расшифровки, судить о теме по подписи, брать меньше авторов. Это бьёт по качеству и экономит копейки.

**Что экономит токены в обоих режимах:**
- субагентам передаются пути к файлам, а не содержимое;
- сырые данные никогда не выводятся в чат;
- digest обрезается до 900 знаков речи на рилс;
- рилсы из запаса лежат списком (ссылка, заголовок, цифры) и разворачиваются по запросу;
- страница, Word и письмо собираются готовыми генераторами из `scripts`, а не пишутся заново каждую неделю.

## 3. Что нужно подключить

| Что | Зачем | Обязательно |
|---|---|---|
| **Apify** (коннектор / MCP-сервер Apify) | Весь сбор данных: Instagram, YouTube, расшифровки | Да. Нужен платный тариф: бесплатного лимита не хватит, а часть акторов на Free отдаёт только первую страницу |
| **Python 3.10+** и `pip install python-docx` | Скрипты пула, генераторы HTML и Word | Да |
| **Gmail** (коннектор Gmail) или SMTP с паролем приложения | Отправка письма | Только для письма |
| Chrome или Edge | Контрольные скриншоты страницы | Желательно |
| Microsoft Word | Обновление оглавления с номерами страниц | Нет |
| Бот кодовых слов (ManyChat, ChatPlace, SaleBot) | Выдача лид-магнитов по слову из комментариев | На стороне человека. Агент только придумывает слова и материалы |

Не нужно: vidIQ, Sandcastles, TikTok-аккаунт, Chrome-расширения, логин в Instagram.

**Работа с Apify.**
- Актор запускается через `call-actor` (`waitSecs: 0` для долгих), статус проверяется через `get-actor-run`, остановка — `abort-actor-run`.
- У каждого запуска ставится `callOptions.maxTotalChargeUsd`.
- Датасет скачивается без токена: `https://api.apify.com/v2/datasets/<datasetId>/items?clean=1&limit=1000&offset=N`. Если вернулся 401, использовать `get-dataset-items` с сохранением в файл.
- Сырые данные никогда не выводятся в чат, только в файлы.

## 4. Нормы объёма ✏️

**Эксперт:** таблица из раздела 2.

**Торговля** (магазины, товары). При первом запуске агент:
1. Просит 5–10 конкурентов, можно русскоязычных: для объёма это допустимо.
2. Собирает их посты и рилсы за 30 дней: `apify/instagram-post-scraper`, `apify/instagram-reel-scraper`.
3. Считает частоту, долю рилсов, каруселей и сторис, лучшие форматы.
4. Предлагает недельный объём и переписывает таблицу раздела 2.
5. Рекомендует дублировать ролики в TikTok, для разведки `clockworks/tiktok-scraper`.

YouTube и подкасты для торговли обычно не нужны. Лид-магниты заменяются акциями, подборками и гидами по выбору.

## 5. Ключевые показатели и пороги

### Рилсы
| Показатель | Как считать | Порог |
|---|---|---|
| Свежесть | дней с публикации | ≤ 14 |
| Комментарии (воронка) | `commentsCount` + призыв «напиши слово» | ≥ `{{ПОРОГ}}` (1000), запасной `{{ПОРОГ_ЗАПАС}}` (600) |
| Аутлаер | просмотры ÷ медиана просмотров последних 12–15 рилсов автора | ≥ ×3 |
| Сильный | комментарии или просмотры | ≥ 1000 комментариев или ≥ 300 тыс. просмотров |
| Язык | язык речи из расшифровки | язык рынка |
| Лимиты плана | | воронок не меньше, чем лид-магнитов в паспорте (обычно 2–3, психологу 1–2) · не больше 2 рилсов одного автора · не больше 3–4 одного формата |

Отношение просмотров к подписчикам не используем. У популярного автора каждый ролик набирает много, и тогда непонятно, залетела ли тема. Ищем ролики, которые сильно выше обычного уровня самого автора, даже если автор маленький.

### Карусели
| Показатель | Порог |
|---|---|
| Свежесть | ≤ 14 дней |
| Комментарии | ≥ 1000, запасной 300 (карусели с тысячей комментариев редкие) |
| Кратность к норме автора | для сортировки |

### YouTube-видео
| Показатель | Порог |
|---|---|
| Свежесть | ≤ 7 дней |
| Длительность | ≥ 15 минут |
| Аутлаер | просмотры ÷ медиана последних 15 видео канала ≥ ×3 (≥ ×2, если таких меньше трёх) |
| Скорость | ролик 1–2 дня и уже на уровне медианы — «растёт» |

### Цифры плана (шапка страницы)
Рилсов в пуле → свежих → расшифровано → в плане; каруселей найдено; YouTube-видео найдено и аутлаеров; сумма комментариев и просмотров отобранных рилсов.

## 6. Воронка недели

```
🎬 Рилс с кодовым словом ──► 💬 слово в комментариях ──► 🤖 бот в директ
        │                                                        │
        │                                                        ▼
        │                                             ✈️ Telegram: 🧲 лид-магнит
        │                                                        │
        ├──► концовка «урок на YouTube» ──► ▶️ YouTube-видео     ▼
        │                                             🔥 прогрев в сторис (1 в неделю)
        └──► «разобрала в подкасте» ──► 🎙 подкаст                │
                                                                 ▼
                                                        💼 продукт / консультация
```

Правила связок:
- **Лид-магнит.** Темы только из рилсов недели, придумывать с нуля нельзя. Один лид-магнит может закрывать несколько рилсов. Если выбранные рилсы дают больше лид-магнитов, чем в паспорте, написать: «выберете рилсы А, Б, В — выйдет N лид-магнитов».
- **Подкаст.** Тема, выросшая из рилсов недели, которую лучше раскрыть голосом. Один рилс ведёт на подкаст своим словом.
- **YouTube.** Если тема YouTube-видео хотя бы отдалённо совпадает с рилсом, агент переписывает концовку рилса: «я записала урок на YouTube, ссылка в шапке».
- **Прогрев в сторис.** Тема, которая повторяется в рилсах недели или болит сильнее всего: люди придут именно с ней. Прогрев расширяет рилс, а не пересказывает его. Прогрев один на неделю: одна тема, выходит в один день — лучше в день рилса или лид-магнита по той же теме.
- **Кодовые слова** — одно короткое русское слово, не повторяются внутри недели и с прошлыми неделями (`history.json`).

## 7. Архитектура: оркестратор и субагенты

Главный агент (оркестратор) **не читает сырые данные**. Он запускает субагентов, передаёт им пути к файлам и получает короткие отчёты. Иначе не хватит памяти.

| # | Субагент | Вход | Выход | Бюджет Apify | Когда |
|---|---|---|---|---|---|
| 1 | Рилсы: сбор и расшифровка | паспорт | `raw\*.json`, `reels_pool.json`, `reels_digest.txt` | до $3 | параллельно с 3 и 4 |
| 2 | Рилсы: редактор-отбор | `reels_digest.txt`, паспорт | `reels_selection.json` | — | после 1 |
| 2б | Рилсы: перевод и раскладка | `reels_selection.json`, расшифровки, пул | `reels.json` | — | после 2 |
| 3 | Карусели | паспорт, авторы | `carousels.json`, `raw\carousels\` | до $1,5 | параллельно |
| 4 | YouTube | паспорт | `youtube.json` | до $2 | параллельно |
| 5 | Стратег | `reels.json`, `carousels.json`, `youtube.json` | `strategy.json` | — | после 2б, 3, 4 |
| 6а | Оформление: HTML + письмо | 4 JSON | `plan-<дата>.html`, `email-<дата>.html`, `email-subject.txt` | — | после 5, параллельно с 6б |
| 6б | Оформление: Word | 4 JSON | `plan-<дата>.docx` | — | после 5 |
| 7 | Отправка и история (сам оркестратор) | файлы | письмо, `history.json` | — | в конце |

В экономном режиме субагентов пять: сбор, отбор, перевод и раскладка, карусели вместе с YouTube, стратег вместе с оформлением (раздел 2б).

Правила:
- Если сбор рилсов большой (больше ~150 кандидатов), редактор-отбор делится на два субагента по половине digest с общими правилами. Потом отдельный шаг сводит результаты.
- Каждому субагенту в задаче передаются: роль, паспорт клиента (путь), нужные разделы этой инструкции, пути входа и выхода, JSON-схема выхода, бюджет, что вернуть в отчёте (коротко, без пересказа данных).
- Субагенты сохраняют JSON и проверяют его `json.load` перед отчётом.
- Оркестратор после оформления сам смотрит 2–3 скриншота и только потом отправляет письмо.

## 9. Этап 1. Рилсы

### 9.1 Сбор (окно 14 дней)
Запускать параллельно, `waitSecs: 0`, потом опрашивать.

**А. Живой поиск** — `memo23/instagram-reels-search-scraper` (≈ $0,0013 за рилс):
```json
{"queries": ["deep work", "morning routine", "time blocking", "burnout recovery", "comment focus"],
 "maxResultsPerQuery": 60, "englishOnly": true}
```
- **Запросы по одному термину.** Оператор OR в этом акторе не работает: он ищет только первый термин и молча теряет остальные. Берём 8–12 отдельных запросов из облака тегов: большая часть с уровня 2 и 3, один-два с уровня 1.
- Запросы-воронки: термин плюс слово `comment` (`comment focus`, `comment attachment`).
- Даты актор не фильтрует, фильтруем сами. Если результаты идут по одному дольше 2–3 минут, остановить: основной объём уже пришёл.

**Б. Булев поиск по свежей ленте** — `scraping_solutions/instagram-boolean-search-scraper-posts-reels` ($0,01 за страницу + $0,00145 за рилс):
```json
{"searchQuery":"{{BOOLEAN_QUERY}}","resultsLimit":100,"contentType":"reels_only","hashtagFeedType":"recent",
 "searchCoverage":"efficient","oldestPostDate":"<сегодня−14>","minimumComments":300}
```
✏️ Здесь OR работает. Не больше 8–10 терминов: на 12 терминах 60 страниц ($0,60) дали 14–19 рилсов. Термины берём с уровней 2 и 3 облака.

**Запас.** Собираем заведомо больше, чем нужно: в план идёт втрое больше рилсов, чем человек снимает (снимает 5 → 15 в плане), плюс `{{ЗАПАС}}` тем списком без перевода. Часть отсеет сам человек, часть — язык и тема.

**В. Авторы** — `apify/instagram-reel-scraper` ($0,0023 за рилс):
```json
{"username":["<30–40 авторов>"],"resultsLimit":12,"skipPinnedPosts":true}
```
Авторы = `{{АВТОРЫ}}` + авторы из А и Б, у которых есть рилсы с ≥300 комментариев или ≥100 тыс. просмотров. Явный мусор (котики, юмор, новостные СМИ) не брать. Этот слой находит свежие аутлаеры и воронки, которых нет в поиске. В нишах вроде психологии без него воронок почти не находится.

### 9.2 Пул
1. Скачать датасеты в `raw\reels_<источник>.json`; файлы авторов называть `reels_authors*.json`.
2. `pool.py` (раздел 19):
   - нормализует поля разных акторов;
   - убирает дубли;
   - считает медиану автора и кратность;
   - отбрасывает старше 14 дней, коды из `history.json` и подписи явно на чужом языке;
   - размечает предварительный слот.

### 9.3 Порядок фильтров (строго)
1. **Цифры:** воронка, аутлаер, сильный (раздел 5). Всё ниже порогов — в «запас», дальше не идёт.
2. **Убрать только стопроцентно чужое** по автору и подписи: котики, фейлы, юмор, новостные СМИ, кулинария, другой язык, стоп-слова `{{СТОП_СЛОВА}}`. Сомнения → оставить. Мусорные шаблоны ниши (экзамены, розыгрыши, «день 137/365», похудение) отсекаются регуляркой в `pool.py`.
3. **Расшифровать всё оставшееся.** Тему по подписи НЕ судим: подпись часто не совпадает с содержанием, а английская подпись не гарантирует английскую речь.
4. **Отбор по тексту** (9.5).

### 9.4 Расшифровка
`steadyfetch/instagram-reel-transcript-scraper` ($0,01 за рилс, ~9 рилсов в минуту):
```json
{"reelUrls":["https://www.instagram.com/reel/<code>/", "…"], "includeOnScreenText": {{БЕЗ_РЕЧИ}}, "maxRunSeconds": 1500}
```
- Статусы: `transcribed`, `onscreen_text_extracted`, `no_speech`, `no_audio_stream`, `private_or_removed` (без списания), `repeat` (уже расшифровывался этим аккаунтом — текст не вернёт, храните расшифровки в папке недели).
- `includeOnScreenText: true` только если человек снимает рилсы без речи.
- Потом `digest.py`: один текстовый файл, в котором у каждого рилса цифры, подпись, речь (до 1500 символов) и текст на экране.

### 9.5 Отбор (субагент-редактор)
1. **Категория:**
   - с речью на языке рынка → кандидат;
   - без речи (титры под музыку) → отдельный список `no_speech` с отметкой `wow`, если ≥1000 комментариев или ≥1 млн просмотров или ×20 и тема в нише; в основные 15 не идут;
   - другой язык речи → отсев.
2. **Отсев с причиной:**
   - не ниша (по `{{НЕ_НИША}}`);
   - держится на личности или опыте автора, который эксперт не повторит («заработал $2 млн», «работаю в Meta», «я нейрохирург» как суть). Если опыт упомянут вскользь — оставить;
   - сложно адаптировать к рынку клиента (местные законы, недоступные сервисы как суть, чужие праздники);
   - дубль темы (из нескольких роликов про одно — один сильнейший);
   - больше 2 от автора;
   - сенсация без проверки.
3. **15 лучших:**
   - 2–3 воронки (призыв + ≥ порога, тема просится в лид-магнит), остальные по силе цифр и пользе;
   - разнообразие форматов: 🛠 инструкция, 📋 список, 🧠 теория наглядно, 💡 инсайт/опыт/мнение, ⚠️ разбор ошибки, 📰 тренд. Не больше 3–4 одного;
   - **профиль стиля** `{{ПРОФИЛЬ_СТИЛЯ}}`: форматы, которые человек любит, ставим чаще и в рекомендуемые; форматы, которых нет в его примерах, — максимум один за неделю и с пометкой «попробуйте, у вас такого не было»;
   - не допускать недели про одно и то же («кодовые слова для ChatGPT» всю неделю);
   - если достойных меньше 15, не добивать мусором: написать, сколько не хватило.

### 9.6 Раскладка и заголовки (субагент «перевод и раскладка»)
- **Дни.** Пн–Пт по 3 варианта. Первым ставится рекомендуемый (`recommended: true`) с причиной: уникальная подача, растущая тенденция, разнообразит неделю, «про это надо сказать сейчас».
- **Разнос.** Воронки в разные дни. В одном дне нет двух рилсов одного автора или формата, варианты дня дают разный угол.
- **Заголовок.** Самое цепляющее место рилса плюс цифра-мотиватор («24 тыс. комментариев за 4 дня»). Эксперт часто смотрит на тему и думает «скучно», поэтому формулировка должна зажигать.
- **Потенциал.** Для каждого рилса отметить, на какой лид-магнит он просится и какое YouTube-видео из него вырастает.
- **Пометки для съёмки.** Что показать на экране, что проверить до съёмки (существует ли функция или скилл), что заменить для рынка клиента.
- **Перевод** — по разделу 15. В экономном режиме целиком переводятся только рекомендуемые пять рилсов, у остальных хук и пересказ в 3–5 фраз; полный текст готовится по запросу.
- **Запас.** Темы, не вошедшие в 15, но прошедшие фильтр по цифрам и языку, сохраняются в `запас.md`: ссылка, автор, цифры, о чём, тег. Без перевода.

## 12. Этап 4. Стратегия недели

1. **Лид-магниты** (`{{ЛИДМАГНИТЫ}}` основных + до 2 запасных). Их не может быть больше, чем найдено рилсов-воронок недели. Количество подстраивается под нишу: не больше, чем есть рилсов-воронок недели и сил у человека. Психологу обычно хватает одного сильного лид-магнита в неделю; если воронок в нише нашлось мало, лучше один, но точный. Для каждого:
   - формат: гайд, чек-лист, инструкция, тест, мини-книга, подборка (промптов, стилей, инструментов), шаблон, библиотека;
   - название и обещание;
   - что внутри (5–7 пунктов);
   - кодовое слово;
   - какие рилсы и карусели ведут;
   - сколько времени сделать;
   - почему заберут (цифры исходных рилсов).

   Можно брать зарубежный материал из рилса как основу: перевести, адаптировать, улучшить.
2. **Подкаст** (1): тема, почему голосом, план 6–7 блоков, какой рилс ведёт и фраза-концовка со словом.
3. **🔥 Прогрев в сторис — один в неделю** (одна тема, выходит в один день).
   - Тема: повторяется в рилсах недели или болит сильнее всего.
   - Выдача: тема, неожиданный угол, что раскрыть (4–6 пунктов как последовательность сторис), почему именно она, день выхода, куда ведёт. Подробный сценарий не пишется.
   - Проверка темы, минимум 2 итерации, после каждой переписки проверять заново:
     1. **Востребована:** есть в рилсах недели.
     2. **Глубже рилса:** расширяет тему, а не повторяет.
     3. **Даёт неожиданный угол:** человек на проблему так не смотрел.
     4. **Не банальна:** не «AI не заменит тебя», «главное — системность», «будь собой», «работай с мышлением».

     Пример уровня для психолога: не «тревога отнимает силы», а «продуктивность бесполезно качать, если 80% сил уходит на перепроверки и тревогу: вот как это увидеть у себя». Лог итераций сохраняется в `check_log`.
4. **YouTube:** выбрать рекомендуемую тему и написать новые концовки для 2–3 связанных рилсов.
5. **Календарь** Пн–Вс: рилс дня (рекомендуемый), 1–2 карусели, прогрев (1 в неделю, в один день), YouTube-видео, подкаст, лид-магниты (в день своего рилса).
6. **Сводка:** неделя в 3 фразах (главная тема, чем подкреплена цифрами, куда всё ведёт) и цифры для шапки.

## 13. Этап 5. Оформление

Цель: человек открывает план и хочет его показать. Премиально, крупно, чисто, с воздухом.

Что собирается, зависит от режима (раздел 2б): полный — страница, Word и письмо с доводкой и скриншот-проверкой; эконом — только страница готовым генератором. Запасные темы в обоих режимах отдаются отдельным файлом `запас.md`: ссылка, заголовок, цифры, тег. Генераторы их не рисуют, разворачиваются они по запросу «разверни тему N».

### 13.1 Жёсткие правила
- **Никаких картинок, превью и скриншотов чужих рилсов, видео и каруселей** (выглядит как «спёрли»). Только эмодзи, типографика, CSS-графика, инлайн-SVG.
- Ссылка на оригинал маленькая и вторичная: «оригинал ↗».
- **Тип видео везде подписан «YouTube-видео»** (чипы, календарь, легенда, письмо, Word).
- **Прогрев в сторис** в календаре встречается один раз.
- **В видимом тексте нет технических кодов рилсов**: только «рилс @автор» или заголовок.
- Весь текст на русском, живой, без канцелярита.

  - форматы: 🛠 📋 🧠 💡 ⚠️ 📰.

### 13.3 HTML-страница (`plan-<дата>.html`)
Самодостаточный файл: CSS и JS внутри, внешняя только ссылка на Google Fonts, без `<img>`.
1. **Hero.** «Контент-план · даты», «для {{ИМЯ}}» в правильном падеже, 3 фразы сводки, декоративный CSS-радар, плитки цифр отбора в моно.
2. **Неделя на ладони.** 7 колонок-дней (на телефоне вертикальная лента), чипы с эмодзи площадки. Клик переносит к деталям.
3. **🎬 Рилсы по дням.** Табы Пн–Пт, в дне 3 карточки, рекомендуемая первая с ⭐ и glow. В карточке:
   - чипы формата и слота, заголовок, метрики;
   - хук в кавычках, «почему рекомендуем»;
   - кнопки «📜 Сценарий» (раскрывается, с длительностью) и «Скопировать»;
   - пилюля кодового слова, «🎥 Для съёмки», «✨ Потенциал»;
   - новая концовка на YouTube, если есть;
   - чекбокс «Беру» (localStorage в try/catch, счётчик в шапке);
   - «оригинал ↗».
4. **🗂 Карусели.** Карточки со слайдами-квадратами 1:1 (номер и русский текст, размер шрифта от длины, горизонтальная прокрутка внутри блока), «почему в плане», кодовое слово, «доступ и правки».
5. **🔥 Прогрев в сторис.** Одна яркая карточка: день, тема, неожиданный угол, что раскрыть, почему сейчас, куда ведёт.
6. **▶️ YouTube-видео.** Рекомендуемая тема крупно: план-таймлайн, почему сейчас, источники с ×N. Остальные компактно («Запасная тема 1–4»). Блок «Тенденции недели».
7. **✈️ Telegram.** Лид-магниты «коробками продукта» (эмодзи-обложка на цветном фоне, обещание, что внутри галочками, слово, какие рилсы ведут, время). Запасные и `note_ru`. Подкаст — карточка с CSS-волной и планом.
8. **🔗 Воронка недели.** Схема с реальными названиями этой недели.
9. **Рилсы без речи.** Компактный список (на телефоне карточки) с пометкой «снимаете такие — скажите агенту».
10. **⚙️ Как собрано.** Воронка отбора цифрами и причины отсева CSS-барами.
11. **Прочее.** Sticky-навигация, плавный скролл, адаптив до 400 px без горизонтального скролла страницы, print-стили.

### 13.4 Письмо (`email-<дата>.html`)
- **Вёрстка.** Ширина 600 px, только таблицы и inline-стили, `bgcolor` на ячейках, без JS, `<style>` и картинок. Шрифты Arial или Segoe UI.
- **Размер** меньше 100 КБ (Gmail обрезает письма больше 102 КБ).
- **Содержание:**
  - hero и 3 фразы;
  - 4 плитки цифр;
  - неделя по дням с эмодзи;
  - ⭐ рекомендуемый рилс каждого дня (заголовок, метрика, хук, слово);
  - 🧲 лид-магниты, 🎙 подкаст, 🔥 прогрев (день), ▶️ YouTube-видео;
  - «Полный план: сценарии, карусели, план видео — во вложениях».
- **Тема письма:** «📅 Контент-план на ДД–ДД месяца: N рилсов, N лид-магнитов, подкаст и YouTube».

### 13.5 Word (`plan-<дата>.docx`, python-docx)
- **Стиль.** Светлый, печатный: текст `#1F2430`, акцент `#F5C518` (подложки заголовков, шапки таблиц), воронки `#E8743B`.
- **Вёрстка.** Шрифт Segoe UI (запасной Arial, прописать и для East Asian/complex через rFonts), текст 10,5–11 pt, межстрочный 1,15, поля 2 см, A4.
- **Титульный лист:** полоса акцента, «Контент-план», неделя и имя, 3 фразы, плитки цифр.
- **Оглавление:** поле TOC. Если есть Word, обновить его автоматически, иначе оставить подсказку «обновите поле».
- **Разделы:**
  - 📅 неделя (таблица);
  - 🎬 рилсы по дням полностью со сценариями;
  - 🗂 карусели (слайды нумерованным списком);
  - 🔥 прогрев;
  - ▶️ YouTube-видео;
  - ✈️ лид-магниты и подкаст;
  - 🔗 воронка;
  - рилсы без речи;
  - ⚙️ как собрано.
- **Разметка страниц:** разрывы страниц между крупными разделами. Колонтитул «Контент-план 2.0 · даты» и «стр. N из M», на титуле без колонтитула.

### 13.6 Проверка оформления
- **Скриншоты.** Headless Chrome или Edge: десктоп 1440 px и телефон 400 px. Headless не сужает окно меньше ~500 px, поэтому телефон снимается через страницу-обёртку с iframe шириной 400 px. Плюс письмо на 700 px. Скриншоты посмотреть глазами и исправить наезды, пустые блоки, контраст, горизонтальный скролл.
- **Подсчёт отрисованного.** Всё отрисовано: 15 рилсов, 3–4 карусели, 3–5 YouTube-тем, лид-магниты, подкаст, 1 прогрев, календарь.
- **Word.** Файл заново открывается python-docx, число элементов совпадает. Если есть Word, сохранить PDF и посмотреть несколько страниц.

## 15. Правила текста

**Перевод и адаптация:**
1. Хук и структуру держать близко к оригиналу: раз сработало, значит работает.
2. Сначала перевод близко к тексту. Потом перечитать и переписать места, которые звучат по-русски криво, не уходя от смысла. Проверить ещё раз. В план идёт только финал.
3. Личная история автора: если ролик держится на ней, он в отсеве. Если упомянута вскользь, переписать в третьем лице («этот парень сделал…») или убрать.
4. Не акцентировать «я перевела/адаптировала».
5. Призыв «напиши слово» оставить, слово перевести одним коротким русским словом.
6. Корявая речь автора (частый случай у авторов с неродным английским): писать чистый сценарий по идее и хуку, а не буквальный перевод.
7. Сервисы, недоступные на рынке клиента: пометить и дать аналог.
8. Сезонные хуки («сентябрь, 4 месяца до конца года») пересчитать под дату выхода.

**Стиль всех текстов плана:**
- живой разговорный русский, коротко;
- без «это не X, это Y», канцелярита, пустых усилителей («невероятный», «мощный»), тройных перечислений ради ритма;
- цифры конкретные: «24 тыс. комментариев за 4 дня», а не «много комментариев».

## 16. Настройка под нишу ✏️

### Облако тегов: от широких тем к узким

Ищем не те же рилсы, что прислал человек, а похожие по смыслу. Поэтому теги держим тремя уровнями.

| Уровень | Что это | Сколько | Пример: продуктивность | Пример: психолог |
|---|---|---|---|---|
| 1. Сфера | широкие темы ниши | 3–5 | productivity, focus, personal brand | anxiety, relationships, self worth |
| 2. Темы | о чём конкретно говорят | 10–15 | deep work, morning routine, time blocking, burnout recovery | anxious attachment, people pleasing, nervous system, boundaries |
| 3. Узкие | инструменты, приёмы, боли | 20–40 | pomodoro alternative, notion second brain, claude skills | freeze response, fawn response, overthinking at night |

- Уровень 1 приносит новизну, уровень 3 — точность. В поиске работают все три.
- Общие слова (`ai`, `love`, `business`, `life`, `success`) не берём: они тянут мусор.
- Рядом ведём стоп-слова `{{СТОП_СЛОВА}}`: что лезет в выдачу, но не подходит.
- Облако живёт в `облако-тегов.md`. Каждую неделю: добавить формулировки, которые дали хорошие находки, убрать пустые, дописать новые стоп-слова. Раз в месяц пересобрать уровень 3 — ниша меняется.

Как облако превращается в запросы:
| Куда | Как |
|---|---|
| memo23 | 8–12 запросов **по одному термину**, OR не работает |
| memo23, воронки | термин плюс слово `comment`, тоже по одному |
| Булев поиск | один запрос, 8–10 терминов через OR |
| YouTube | 8–12 запросов из 2–4 слов |

Первый набор тегов собирается при первом запуске из рассказа человека и разбора его примеров рилсов (файл `1-ПЕРВЫЙ-ЗАПУСК.md`, шаги A–B).

### «Не ниша» — примеры
- **Маркетолог:** код и разработка для программистов, поиск работы и IT-сертификаты, AI-фото ради красоты без пользы для бренда, «как получить ChatGPT бесплатно».
- **Психолог:** эзотерика, астрология, нумерология, «знаки вселенной», йога без психологии, питание и ЖКТ, юмор, котики, новости.

### Что мы знаем про ниши (тест 15.09.2026)
- **AI и маркетинг:**
  - воронок с 1000+ комментариев за 14 дней много (десятки);
  - главная задача — отсеять код для разработчиков (30 из 172) и чужие языки (33 из 172, в основном хинди при английской подписи);
  - дубли трендов недели: ~20 роликов про один и тот же новый инструмент.
- **Психология:**
  - воронок с 1000+ мало (2–4), почти все находятся через слой авторов;
  - около трети сильных рилсов — без речи, в титрах, и именно у них самые большие цифры, поэтому вопрос `{{БЕЗ_РЕЧИ}}` критичен;
  - много эзотерики и развлечений под теми же хэштегами;
  - хвост списка слабее, поэтому допустимо отдать меньше 15 и честно это написать.
- **Карусели.** С 1000+ комментариев встречаются редко даже в сильной нише, обычно срабатывает порог 300.
- **YouTube-видео.** В нишах часто есть свободные форматы: например, по «instagram growth» длинных роликов почти нет, только шорты. Это стоит отмечать как возможность.

## 18. Грабли
- **memo23 не понимает OR:** при запросе `a OR b OR c` ищет только `a`, остальное молча теряется. Только по одному термину на запрос.
- Поиск по темам даёт 8–11% свежих рилсов, остальное старое: вытаскиваем с запасом и обязательно добавляем слой авторов.
- Однословные запросы на YouTube тянут ASMR, музыку для сна и медитации.
- `apify/instagram-search-scraper` (поиск «popular») выдаёт старый вечнозелёный топ и часто блокируется. Поиск по хэштегу (`apify/instagram-hashtag-scraper`) выдаёт свежий мусор. Не использовать.
- Поиск «за неделю» у `scrapeforge/instagram-scraper-all-in-one` и `khadinakbar/instagram-hashtag-scraper` отдаёт единицы рилсов.
- Живой поиск (memo23) в конце отдаёт результаты по одному: останавливать.
- Английская подпись не гарантирует английскую речь. Язык проверяется только по расшифровке.
- Расшифровщик не отдаёт текст повторно (`repeat`): сохранять расшифровки сразу.
- `private_or_removed` бывают у 3–6% рилсов: пропускать (без списания).
- В выдаче reel-scraper бывают коллабы с чужими аккаунтами, профильные строки без `shortCode` и `likesCount = -1` (лайки скрыты — смотреть на просмотры).
- Ссылки на видео и картинки Instagram протухают за часы: слайды каруселей скачивать сразу.
- Медиана автора считается минимум по 5 рилсам, иначе кратность не считается.
- Отношение просмотров к подписчикам на YouTube вводит в заблуждение: только медиана канала.
- Письмо больше 102 КБ Gmail обрезает.
- Google Fonts в Gmail не грузятся, в письме только системные шрифты.

## 19. Скрипты

Готовые реализации лежат в `scripts\`. Если папки нет, агент пишет скрипты сам по этой спецификации.

| Скрипт | Вход | Что делает | Выход |
|---|---|---|---|
| `fetch_dataset.py <datasetId> <out.json>` | id датасета Apify | Скачивает все страницы по 1000 без токена | JSON-массив |
| `pool.py <папка_недели> <префикс>` | `raw\<префикс>_*.json`, `history.json` | Нормализует поля трёх схем. Код → ссылка. Считает возраст, медиану автора по файлам `*authors*` (≥5 рилсов) и кратность. Убирает дубли, старше 14 дней, коды из истории, чужой язык подписи (эвристика по алфавиту и частым словам). Помечает призыв регуляркой (comment/drop/type/reply/DM + слово) и предварительный слот: воронка (призыв + ≥порога), воронка-запас, аутлаер (×3), сильный (≥1000 комм. или ≥300 тыс. просмотров), запас | `<префикс>_pool.json`, `<префикс>_review.txt` (всё кроме «запаса») |
| `digest.py <папка> <префикс> <расшифровки…>` | пул и JSON расшифровок | Склеивает цифры, подпись, речь (до 1500 симв.) и текст на экране (`onScreenText.rawText` / headline+body+cta). При дублях берёт запись с текстом | `<префикс>_digest.txt`, `<префикс>_transcripts.json` |
| `build_plan_html.py [папка_недели]` | 4 JSON этапов | Страница и письмо по разделу 13: html.escape всех строк, «@@» → «@», склонения чисел, замена кодов рилсов в видимом тексте на автора или заголовок | `plan-*.html`, `email-*.html`, `email-subject.txt` |
| `build_plan_docx.py --week <папка_недели> [--no-word] [--pdf путь] [--out путь]` | 4 JSON этапов | Word по разделу 13.5, обновление оглавления через Word, если он есть | `plan-*.docx` |

| лайки | likeCount | likeCount | likesCount |

| автор | username | username | ownerUsername |
| подпись | caption | caption | caption |
