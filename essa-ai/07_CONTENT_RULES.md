# CONTENT RULES
## Правила создания контента без разрушения воронки

---

# 1. ГЛАВНОЕ ПРАВИЛО

Контент — НЕ набор самостоятельных публикаций.

Каждый материал выполняет определённую психологическую работу.

Перед написанием определить:

FUNNEL_STAGE:

FUNCTION:

BELIEF_BEFORE:

BELIEF_AFTER:

MAIN_IDEA:

PROOF:

NEXT_STEP:

CTA:

---

# 2. BELIEF BEFORE → BELIEF AFTER

Материал считается готовым, только если понятно:

# ЧТО ЧЕЛОВЕК ДУМАЛ ДО?

и

# ЧТО ОН ДОЛЖЕН ДУМАТЬ ПОСЛЕ?

Пример:

BEFORE:

> «Мне надо изучать AI».

AFTER:

> «Мне нужно решить конкретную ручную задачу».

Если сдвиг не произошёл — контент не выполняет свою функцию.

---

# 3. ОДИН МАТЕРИАЛ = ОДНА ГЛАВНАЯ МЫСЛЬ

Не пытаться в одном посте:

- обучить;
- рассказать историю;
- продать;
- закрыть пять возражений;
- показать десять инструментов.

---

# 4. ОДИН МАТЕРИАЛ = ОДИН CTA

Не:

> подпишись + сохрани + напиши + купи + перешли другу.

Выбрать главное действие.

---

# 5. СТРУКТУРА КАРУСЕЛИ

Карусель — психологический маршрут.

Типовая структура:

# HOOK

↓

# IDENTIFICATION

↓

# PROBLEM

↓

# CONFLICT

↓

# PATTERN INTERRUPT

↓

# NEW BELIEF

↓

# MECHANISM / PROOF

↓

# BRAND IDEA

↓

# CTA

---

# 6. ФУНКЦИЯ СЛАЙДОВ

Пример:

SLIDE 1:
attention.

SLIDE 2:
identification.

SLIDE 3:
problem expansion.

SLIDE 4:
conflict.

SLIDE 5:
pattern interrupt.

SLIDE 6:
new paradigm.

SLIDE 7:
examples.

SLIDE 8:
framework.

SLIDE 9:
insight.

SLIDE 10:
brand anchoring + CTA.

Можно менять количество слайдов.

Нельзя удалять ключевой смысловой переход.

---

# 7. ЧТО МОЖНО МЕНЯТЬ В КАРУСЕЛИ

Можно:

- сокращать предложения;
- усиливать hook;
- адаптировать Tone of Voice;
- улучшать дизайн;
- менять примеры, если они реальны;
- делать слайд короче.

---

# 8. ЧТО НЕЛЬЗЯ МЕНЯТЬ БЕЗ ПРИЧИНЫ

Нельзя:

- переставлять смысловые блоки;
- удалять промежуточное убеждение;
- делать продажу раньше;
- добавлять несуществующий кейс;
- менять основной CTA.

---

# 9. REELS

Предпочтительная структура:

# HOOK
первые 1–2 секунды.

↓

# CONTEXT

↓

# PROBLEM

↓

# TURN

↓

# MECHANISM

↓

# RESULT

↓

# MAIN IDEA

↓

# CTA

---

# 10. ПРЕДПОЧТИТЕЛЬНЫЕ REELS-ФОРМАТЫ

Учитывая сильные стороны автора:

- voice-over;
- screen recording;
- workflow;
- демонстрация;
- before/after;
- текст на экране;
- интерфейсы;
- процесс.

Talking head не обязателен.

---

# 11. HOOK

Не:

> «Сегодня расскажу об автоматизации монтажа».

Лучше:

> «До 3 часов → около 20 минут».

Или:

> «Тебе не нужно изучать нейросети».

Или:

> «Вот это я бы НЕ автоматизировала».

Hook должен вести в основной смысл, а не быть кликбейтом, не связанным с материалом.

---

# 12. STORIES

Функции Stories:

- исследование;
- опрос;
- диалог;
- behind the scenes;
- доказательство;
- возражение;
- маленький смысл;
- продажа после прогрева.

Не делать Stories отдельной изматывающей системой.

---

# 13. ВИДЫ STORIES

## Процесс

«Сегодня тестирую...»

## Ошибка

«Вот это не сработало...»

## Опрос

«Сколько занимает монтаж?»

## Результат

«Было → стало».

## Мысль

«Одна кнопка — это финал».

---

# 14. ПРОДАЮЩИЙ КОНТЕНТ

Три уровня:

## Продажа проблемы

Человек видит цену своей ручной работы.

---

## Продажа механизма

Человек видит:

как именно проблема решается.

---

## Продажа продукта

Только после этого:

AI-Мастерская.

---

# 15. PAS

Разрешённая структура:

PROBLEM:

реальная узнаваемая проблема.

AGITATION:

показать последствия без искусственного запугивания.

SOLUTION:

новый процесс / продукт.

---

# 16. НЕ ИСПОЛЬЗОВАТЬ

Без необходимости не использовать:

- искусственный страх;
- «ты безнадёжно отстал»;
- фальшивый дефицит;
- магическую кнопку;
- «AI полностью заменит тебя»;
- громкие обещания без доказательств.

---

# 17. ФАКТЫ

Не придумывать:

- цифры;
- количество клиентов;
- кейсы;
- результаты;
- экономию;
- отзывы;
- длительность процесса.

Если доказательства нет:

не добавлять.

---

# 18. КЕЙС 3 ЧАСА → 20 МИНУТ

Правильно:

> «В одном из реальных сценариев похожий процесс сократился примерно с трёх часов до двадцати минут вместе с правками».

Неправильно:

> «Я сокращу тебе монтаж до 20 минут».

---

# 19. TONE OF VOICE

Использовать отдельный файл пользователя.

Этот файл НЕ должен заменять Tone of Voice.

Он регулирует только:

- смысл;
- функцию;
- структуру;
- воронку.

---

# 20. СООТНОШЕНИЕ ПОЛЬЗЫ И ПРОДАЖИ

Дни 1–7:

не активная продажа.

Дни 8–14:

метод и доверие.

Дни 15–21:

первый бесплатный результат.

Дни 22–30:

продажа.

---

# 21. КОНТЕНТНЫЕ РУБРИКИ

Разрешённые центральные рубрики:

- Я проверила за тебя.
- Не автоматизируй это.
- Путь к одной кнопке.
- AI для конкретного эксперта.
- Было → стало.
- Честный AI.
- Одно внедрение.
- Лаборатория.

---

# 22. ЧТО НЕ ДОЛЖНО СТАТЬ ОСНОВОЙ

Не строить бренд вокруг:

- новостей AI;
- ежедневных обновлений;
- списков сервисов;
- обзоров функций без рабочего контекста.

---

# 23. БЕСПЛАТНЫЙ КОНТЕНТ

Должен быть полезным сам по себе.

Не использовать намеренно неполные инструкции ради продажи.

---

# 24. ПРОВЕРКА ПЕРЕД ПУБЛИКАЦИЕЙ

[ ] Я знаю этап воронки.

[ ] Я знаю функцию.

[ ] BELIEF BEFORE определён.

[ ] BELIEF AFTER определён.

[ ] Между ними есть реальный переход.

[ ] Есть один главный смысл.

[ ] Есть один CTA.

[ ] CTA соответствует этапу.

[ ] Нет преждевременной продажи.

[ ] Нет придуманных фактов.

[ ] Кейсы не превращены в гарантии.

[ ] Автор не превратился в AI-обзорщика.

[ ] Человек понимает, какую его реальную работу обсуждаем.

[ ] Сохранена брендовая идея.

Если хотя бы один критичный пункт нарушен — материал исправить до публикации.

---

# 25. ГЛАВНЫЙ КРИТЕРИЙ

Не:

> «Получился ли красивый пост?»

А:

# «СДЕЛАЛ ЛИ ЭТОТ ПОСТ СВОЮ РАБОТУ В ВОРОНКЕ?»
