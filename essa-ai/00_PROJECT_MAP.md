# PROJECT MAP
## Карта источников, приоритетов и конфликтов проекта «Моя воронка»

> Назначение файла:
>
> этот документ НЕ содержит новую стратегию.
>
> Он объясняет AI, **какой файл за что отвечает, какой источник читать первым и какой файл имеет приоритет при конфликте**.
>
> Этот файл не должен переписывать содержимое SOURCE OF TRUTH. Он только маршрутизирует к ним.

# 1. ГЛАВНЫЙ ПРИНЦИП

Для каждого запроса сначала определить предмет задачи, затем использовать **самый узкий профильный источник**.

Не выбирать MASTER PROMPT автоматически только потому, что он самый большой.

Не выбирать AgentOS skill автоматически только потому, что он содержит готовую методику.

Приоритет:

# ТЕКУЩИЙ ЗАПРОС ПОЛЬЗОВАТЕЛЯ
↓
# ПРИНЯТЫЕ РЕШЕНИЯ
↓
# ПРОФИЛЬНЫЙ SOURCE OF TRUTH
↓
# MASTER PROMPT
↓
# AGENTOS / МЕТОДИКА ВЫПОЛНЕНИЯ
↓
# ОБЩИЕ ЗНАНИЯ МОДЕЛИ

# 2. ПРАВИЛО ПРИОРИТЕТОВ

## УРОВЕНЬ 1 — текущий прямой запрос Катерины

Явная инструкция в текущем диалоге имеет самый высокий рабочий приоритет.

Если запрос меняет ранее принятое решение:

- не отменять старое решение молча;
- обозначить конфликт;
- при необходимости оформить изменение как `PROPOSED DECISION`.

---

## УРОВЕНЬ 2 — принятые решения

### `11_DECISION_LOG.md`

Главный источник по:

- уже принятым стратегическим решениям;
- решениям, принятым к тесту;
- рабочим стратегическим решениям;
- новым подтверждённым наблюдениям;
- результатам тестов.

### Что он перекрывает

Если в старом MASTER PROMPT или другом документе записана предыдущая версия решения, а в `11_DECISION_LOG.md` есть более новая принятая запись, использовать последнюю принятую запись.

### Что он НЕ делает

`11_DECISION_LOG.md` не заменяет профильные документы целиком.

Он фиксирует изменения и статус решения.

AI не имеет права самостоятельно записывать предложение как `ПРИНЯТО`.

Новая идея AI = `PROPOSED DECISION`.

# 3. ПРОФЕССИОНАЛЬНЫЙ СТАТУС, ОПЫТ И СТЕК

## Главный источник

### `EXPERTISE.md`

Использовать первым для вопросов:

- кто Катерина профессионально;
- какой коммерческий опыт подтверждён;
- какие проекты являются клиентскими;
- какие проекты являются собственными разработками;
- есть ли production-опыт;
- какой технический стек актуален;
- какие инструменты нельзя автоматически приписывать Катерине;
- какие профессиональные заявления допустимы.

### Приоритет

`EXPERTISE.md`
>
`09_CASES_AND_PROOF.md`
>
`MASTER PROMPT`

в вопросах текущего профессионального статуса, клиентского опыта и актуальности стека.

### Важное правило

Если MASTER PROMPT содержит историческую или более широкую формулировку, а `EXPERTISE.md` содержит более конкретное текущее ограничение, использовать `EXPERTISE.md`.

Не смешивать:

- собственные разработки;
- клиентские проекты;
- production-внедрения;
- коммерческую специализацию.

# 16. АЛГОРИТМ ДЛЯ AI ПЕРЕД ЛЮБОЙ СЛОЖНОЙ ЗАДАЧЕЙ

1. Определи предмет задачи.
2. Найди профильный SOURCE OF TRUTH по этой карте.
3. Проверь `11_DECISION_LOG.md`, если задача затрагивает стратегическое решение.
4. Прочитай только релевантные файлы, а не весь проект без необходимости.
5. Определи факт / решение / гипотезу / цель.
6. Если задача контентная — восстанови FUNNEL_STAGE и FUNCTION.
7. Только после этого выбери AgentOS skill.
8. Выполни задачу.
9. Проверь результат на конфликт с проектными ограничениями.
10. Если обнаружен стратегический конфликт — не исправляй стратегию молча.

# 17. КАК РАЗРЕШАТЬ КОНФЛИКТЫ

## Сценарий A
MASTER PROMPT говорит одно, профильный SOURCE OF TRUTH — другое.

→ использовать профильный SOURCE OF TRUTH.

---

## Сценарий B
Профильный файл говорит одно, а `11_DECISION_LOG.md` содержит более новое принятое решение.

→ использовать последнее принятое решение и профильный файл как базовый контекст.

---

## Сценарий C
AgentOS рекомендует маркетинговый или контентный приём, который ломает воронку.

→ отказаться от этой части skill и сохранить воронку.

---

## Сценарий D
AgentOS предполагает инструмент, которого нет в ChatGPT.

→ использовать `CAPABILITY_MAPPING(1).md`.

Не утверждать, что исходный инструмент был вызван.

---

## Сценарий E
Два файла содержат разные доказательные заявления.

→ использовать более консервативную подтверждённую версию и обозначить конфликт, если он важен.

---

## Сценарий F
Катерина прямо меняет решение в текущем сообщении.

→ текущий запрос имеет рабочий приоритет.

Если изменение стратегическое, предложить зафиксировать его в `11_DECISION_LOG.md`.
