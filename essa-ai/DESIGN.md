# 1. ВИЗУАЛЬНАЯ ЗАДАЧА БРЕНДА

Визуал должен поддерживать смысл:

**НЕ БОЛЬШЕ ИИ. МЕНЬШЕ ЛИШНЕЙ РАБОТЫ.**

Ощущение от материалов:

- современно;
- структурно;
- технологично;
- спокойно;
- понятно;
- уверенно;
- без визуального шума;
- без «нейросетевого глянца» ради самого глянца;
- без ощущения аккаунта про бесконечные обзоры нейросервисов.

Главный принцип:

**сначала смысл и функция материала → потом визуальное оформление.**

Дизайн не должен усложнять то, что можно объяснить проще.

# 12. VISUAL RHYTHM — КАРУСЕЛЬ

STATUS: `DECISION — ACTIVE DESIGN RULE`

Карусель должна быть цельной, но не монотонной.

Перед рендером каждому слайду назначить визуальный тип:

```text
PHOTO
TEXT
CARD
SCHEME
PROCESS
STATEMENT
CTA
```

Визуальный тип — это внутренний production-инструмент. Он не меняет смысловую функцию слайда.

## Главные правила ритма

1. Не использовать одну и ту же доминирующую композицию на двух соседних слайдах по умолчанию.

Например, избегать:

```text
PHOTO RIGHT + TEXT LEFT
→
PHOTO RIGHT + TEXT LEFT
```

или:

```text
BIG QUOTE CARD
→
BIG QUOTE CARD
```

Повтор допустим только как осознанный смысловой приём.

2. Два `PHOTO-DOMINANT` слайда подряд по умолчанию не использовать.

Исключение — когда изображения образуют смысловую пару, например:
- before → after;
- comparison;
- последовательность одного события;
- доказательная пара, где оба изображения действительно нужны.

3. После визуально тяжёлого слайда желательно дать более спокойный visual reset:
- text-first;
- statement;
- схема;
- минимальная карточка;
- свободная композиция с большим количеством воздуха.

Не чередовать механически по шаблону `фото → текст → фото → текст`. Цель — ритм, а не шахматный порядок.

4. `BRAND IDEA` и `CTA` должны визуально различаться.

По умолчанию:

```text
BRAND IDEA → text-first / statement slide
CTA        → отдельная CTA-композиция; фото допустимо
```

Не использовать для последних двух слайдов одинаковый photo-layout.

5. Перед финальным render обязательно посмотреть карусель целиком как последовательность, а при доступном render — как contact sheet / общий preview всех слайдов.

Проверить:
- нет ли двух почти одинаковых соседних композиций;
- нет ли серии одинаковых карточек;
- нет ли серии фотографий без смысловой причины;
- не повторяется ли один визуальный жест слишком часто;
- усиливается ли финал, а не повторяется;
- сохраняется ли один визуальный мир бренда.

6. Если ритм слабый, менять:
- композицию;
- visual type;
- масштаб блоков;
- расположение фото;
- плотность;
- визуальный акцент.

Не менять ради ритма:
- `FUNNEL_STAGE`;
- `FUNCTION`;
- `BELIEF_BEFORE → BELIEF_AFTER`;
- `MAIN_IDEA`;
- `PROOF`;
- `NEXT_STEP`;
- `CTA`;
- смысловой порядок.

# 16. ФОТО

STATUS: `DECISION — ACTIVE DESIGN RULE`

Фото должно помогать смыслу, а не заполнять пустое место.

Допустимо:
- портрет;
- рабочая сцена;
- screen/workflow context;
- затемнённое или размытое фото как фон;
- отдельная photo-zone.

## COVER PHOTO

На первом слайде фотография может быть:
- более яркой;
- более контрастной;
- визуально самостоятельной;
- одним из главных элементов hook-композиции.

Её задача — помочь остановить внимание, не мешая считыванию заголовка.

## INTERNAL PHOTOS

На внутренних слайдах фотография должна быть вторична по отношению к смыслу и тексту.

Для dark styles по умолчанию:
- слегка затемнять фото;
- рабочий ориентир затемнения: примерно `15–25%`;
- при необходимости немного снижать контраст;
- допускается лёгкая холодная тонировка под graphite / violet palette;
- текст и ключевой смысл должны считываться раньше фотографии.

Не затемнять механически, если фото уже достаточно спокойное и не конкурирует с текстом.

## PHOTO PURPOSE CHECK

Для каждого фото перед использованием спросить:

**«Что оно добавляет этому конкретному слайду?»**

Фото допустимо, если оно:
- показывает автора;
- поддерживает реальную ситуацию;
- создаёт нужный человеческий контакт;
- показывает процесс;
- является доказательством / результатом;
- помогает функции конкретного слайда.

Если ответ только:

**«Чтобы было красивее»**

— фото не использовать.

## Общие правила

- не деформировать лицо;
- не закрывать лицо текстом;
- не использовать случайный crop;
- не делать фотоколлаж ради заполнения;
- не использовать фото как filler;
- не ставить два photo-dominant слайда подряд без осознанной смысловой причины;
- если фото не добавляет смысла — не использовать.

Нейрофото не является обязательной частью каждого материала.

# 17. ОБЛОЖКИ

Принцип:

**один сильный тезис + один главный визуальный акцент.**

Для обложки:
- `Roboto Condensed Bold`;
- 1–4 строки;
- graphite или light-lavender background;
- один violet-accent;
- максимум один основной объект / фото / интерфейс;
- много воздуха.

Не делать:
- длинный подзаголовок на 6 строк;
- много иконок;
- пять цветов;
- 3D ради 3D;
- длинный CTA на обложке.

# 24. VISUAL QA

Перед выдачей проверить:

[ ] материал выполняет свою функцию;  
[ ] `BELIEF_BEFORE → BELIEF_AFTER` сохранён;  
[ ] CTA не изменён;  
[ ] proof не усилен;  
[ ] выбран только один активный style-mode;  
[ ] используется `Roboto Condensed Bold + Open Sans`;  
[ ] используется core palette;  
[ ] нет yellow core-accent (оранжевый разрешён с 2026-09-22);  
[ ] нет STYLE_03 / STYLE_04 / STYLE_05;  
[ ] нет clipping;  
[ ] нет нечитаемого мелкого текста;  
[ ] нет текста поверх лица;  
[ ] главный акцент считывается первым;  
[ ] визуал не перегружен;  
[ ] material выглядит как часть одной дизайн-системы;  
[ ] просмотрена карусель целиком как последовательность;  
[ ] при доступном render просмотрен contact sheet / общий preview;  
[ ] соседние слайды не повторяют одну dominant composition без причины;  
[ ] нет двух photo-dominant слайдов подряд без осознанной смысловой причины;  
[ ] внутренние фото не перетягивают внимание с текста;  
[ ] BRAND IDEA и CTA визуально различаются;  
[ ] финальные слайды усиливают завершение, а не повторяют друг друга.
