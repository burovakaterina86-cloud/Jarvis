# 2026-10-06 — сборку рилса (`remake`) не запускать в фоне

Рилс «монтаж в Клод Код» (IMG_2660, 22 с): две сборки через `run_in_background` оборвались вместе с сессией моста («didn't finish before the previous session ended»). Остановились на шаге 6/7 (кадры анимации) и оставили папку `frames/` с дырами (кадры 1–~280 пропали) — следующий запуск упал в ffmpeg: `Could find no file or sequence with path 'frames/%05d.png'`.

Что помогло: проверить, что висящих процессов нет, и запустить `remake` **в обычном (не фоновом) вызове** с `timeout` 600000 — он сам стирает `frames/` и рисует заново; прошло за ~2 минуты.

Правило: короткий рилс (до ~1,5 мин, сборка ≤ 8 мин) собирать в переднем плане с максимальным timeout; фон — только если сессия точно не закончится. После оборванного запуска сначала проверить процессы, потом пересобрать целиком (`remake` чистит кадры сам).

Навык `reel-montage` (шаг 8) советует «запусти фоном» — расходится с этим; поправка навыка только через владелицу.

**Обновление (её решение и правка 2026-10-06, вечер):** передний план тоже не годится — он держит весь чат. Теперь сборку ставят в очередь бота: `python -m integrations.jobs submit …`, ход заканчивают, бот пришлёт ролик сам. Рендер защищён замком и проверкой числа кадров. Навык `reel-montage` уже поправлен.
