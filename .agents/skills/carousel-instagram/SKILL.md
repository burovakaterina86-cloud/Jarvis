## Визуальный язык — неизменные правила

- Шрифты (её решение 2026-09-25): заголовки — **Oswald капсом**, текст — **Open Sans**. Других шрифтов нет.
- Рукописная мысль на обложке — **не шрифт, а картинка её почерком** (её слова: «шрифт всё равно не совпадает…
  возьми именно из этого референса, не заменяй другим script-шрифтом»). Сборка обложки сама генерирует её
  по вырезкам почерка из её референсов (`essa-ai/visual_references/обложки на посты/handwriting/`),
  убирает фон и обрезает поля; тот же текст второй раз не генерирует. **Проверь надпись глазами на
  опечатки** — ошибка → удали `visuals/<имя>-hand.png` и собери снова (не больше двух раз), не вышло —
  `"hand_style": "font"` в `cover.json` (запасной Marck Script) и скажи ей.
- Акцент — **фиолетовый** (`[[слова]]` в тексте). Оранжевого и жёлтого нет нигде.
- Фоны — **тёмный и светлый по очереди**, начиная с тёмного (сборка делает сама).
- **Плашки, стрелки, иконки** — line-иконки одного веса, эмодзи и 3D не смешивать.
- **Воздуха не слишком много** — блоки растягиваются на высоту слайда. Простор — только на обложке-хуке.
- Шапка каждого слайда: `01 / 08 ──── МЕТКА`. Метка — её слово-рубрика, не служебная функция.

## Порядок работы

Её слова — порядок, который держу всегда:

1. проанализируй смысл;
2. разбей материал на слайды;
3. придумай отдельную визуальную метафору для каждого слайда;
4. составь storyboard;
5. проверь, чтобы композиции и визуальные объекты не повторялись.

Для каждого слайда — её вопрос: «какой кадр или объект лучше всего показывает эту мысль без текста?»
Storyboard здесь — карта ритма (шаг 2) и поле `_rhythm` в `slides.json`.

### 1. Текст
Текст приходит готовым (комплект `content-plan`) или пишется: бриф → функции слайдов → `textwriter` →
`humaniser`. Утверждённый текст не переписываю: только переносы строк и акцент `[[…]]`.
CTA — только утверждённый в её воронке (`05_FUNNEL.md`); нового не придумываю — нет CTA → спрашиваю.

### 2. Карта ритма — до сборки, обязательно
Каждому слайду — функция по её §13 и тип слайда:

```text
01 HOOK              → photo      (её фото на весь кадр)
02 IDENTIFICATION    → text       (заголовок + текст + плашка-вывод)
03 PROBLEM           → statement  (огромная фраза)
04 CONFLICT          → cards      (карточки с иконками)
05 NEW BELIEF        → steps      (нумерованные плашки со стрелками)
06 MECHANISM / PROOF → compare    (было → стало)
07 BRAND IDEA        → text / statement
08 CTA               → photo      (её фото + плашка CTA)
```

Число слайдов — по смыслу. Проверка: соседние слайды разного типа; двух фото подряд нет;
BRAND IDEA и CTA выглядят по-разному; тип подходит функции. Карту пишу в `slides.json` полем
`"_rhythm"` — владелице без запроса не показываю.

### 3. Её фото — первый и последний слайд
Её решение: сгенерированные кадры с ней — **только на первом и последнем слайде**.

**Её кадр — по её правилам `essa-ai/IDENTITY_LOCK.md` (читать перед любым кадром с ней).** Выбор строго по порядку
(её слова 2026-09-25: «реальное фото + дизайн → предпочтительный вариант; редактирование фото → когда надо изменить
сцену; полная генерация по reference → только когда первые два не подходят»):
1. **Реальное фото + дизайн — по умолчанию.** Бери её настоящее фото из `essa-ai/photo/` (индекс — `README.md`)
   с подходящей позой и встрой в вёрстку (`photo` у слайда / обложки). Лицо 100% её, генерации нет.
   **Тёмная обложка — `portraits/face-main-selfie-black.jpg` целиком, без вырезания** (фон на фото уже тёмный,
   вёрстка сама растворяет левый край; `photo_width` 0.5, `focus` "38% 20%" — лицо не заходит под заголовок).
   Вырезанный фон с рваными краями она не принимает (её поправка 2026-09-25). Фото у неё не просишь —
   карусель собираешь сам из `essa-ai/photo/`.
2. **Правка её фото — когда нужна другая сцена, одежда, свет, предмет.** Её фото — первым `--ref`, лицо не трогается:
   `.venv\Scripts\python.exe -m integrations.visuals.imagegen "какой должна стать сцена" <папка>\visuals\<имя>.png --ratio 4:5 --ref essa-ai/photo/portraits/<её фото> --edit "что именно менять"`
3. **Полная генерация по её фото — только если нужной позы/сцены нет ни на одном её фото:** `--her` (без `--ref`
   генератор сам берёт её набор из проекта в порядке main → front → three-quarter → профили; нет фото — генерации
   не будет). Модель — Nano Banana 2 (запасная GPT Image 2.5): обе умеют image conditioning. Описывать её лицо
   словами запрещено — только её фото.
**Проверка сходства после 2 и 3 — обязательна:** исходник рядом с результатом — глаза (форма, посадка, цвет), брови,
нос, губы, овал, подбородок, скулы, лоб, линия роста волос, возраст, тон и текстура кожи, пропорции.
Поплыло — отклоняешь и идёшь на ступень ниже (к её реальному фото), не больше двух попыток. «Красиво» — не
критерий, критерий — «это тот же человек».

- Сначала её готовые фото (`essa-ai/photo/README.md`); подходящего нет — генерирую по образцу:
  `.venv\Scripts\python.exe -m integrations.visuals.imagegen "промпт" <папка>\visuals\<имя>.png --ratio 4:5 --ref essa-ai/photo/portraits/face-main-selfie-black.jpg --ref essa-ai/photo/portraits/face-front-studio.png --ref essa-ai/photo/portraits/face-selfie-2.jpg --ref essa-ai/photo/portraits/face-reference.jpg --ref essa-ai/photo/portraits/face-profile-left.png --ref essa-ai/photo/portraits/face-profile-right.png`
  (главное селфи первым, студийный анфас, два селфи, два профиля — её образцы 2026-09-25, все всегда; волосы — **холодный бежевый блонд**, зашито в генератор)
- **Причёска и одежда в каждом сгенерированном кадре — другие, чем на её фото** (её правило 2026-09-25,
  зашито в `KEEP_FACE`); в промпте называешь новую причёску и новую одежду под сцену, цвет волос не трогаешь.
- Одежда на её кадрах — **современная, расслабленная, не строгая классика** (её слова 2026-09-25); это
  правило уже зашито в генератор (`KEEP_FACE`), в промпте костюмов и пиджаков не заказываю.
- В промпте: она **в правой половине кадра**, слева тёмная спокойная стена под текст; вечерний
  боковой свет, графитовые и приглушённо-фиолетовые тени; одежда и сцена — под смысл слайда.
- Кто рисует и сколько стоит — «Картинки» ниже.
- Готовый кадр — **глазами**: похожа на образец, черты и возраст те же, нет логотипов и надписей,
  руки целые. Не так — перегенерирую.
- Внутренние слайды без фото — их смысл несут плашки, схемы, карточки.

### 4. `slides.json` → сборка
Файл в папке комплекта `essa-ai/content/<дата>-<тема>/slides.json`:

```json
{"_rhythm": "01 HOOK→photo · 02 …", "slides": [
  {"type": "photo", "label": "Голос", "photo": "visuals/cover-her.png",
   "zoom": 1.1, "shift_x": 9, "text_width": 0.56,
   "hook": "Нейросеть\nпишет\n[[не твоим\nголосом?]]", "body": "Это поправимо.\nЗа один вечер."},
  …
]}
```

```text
.venv\Scripts\python.exe -m integrations.visuals.editorial <папка комплекта>
```

Выход: `visuals/slide-01.png …`, их `.html` и **`visuals/contact-sheet.png`** — все слайды на одном листе.
В отчёте сборки строки `ритм: …` (два фото подряд, одинаковый тип рядом) и `нет файла фото` — исправляю
до выдачи. Код выхода не 0 — PNG не сняты: так и говорю, «готово» не пишу.
Полный образец — `essa-ai/content/2026-09-25-golos-karusel/slides.json`.

### 5. Поля слайдов

| Тип | Поля | Когда |
|---|---|---|
| `photo` | `photo`, `hook`, `body`, `cta`, `cta_icon`, `focus`, `zoom`, `shift_x`, `text_width` | хук и CTA — её фото на весь кадр, текст слева на затемнении |
| `statement` | `hook`, `body` | проблема, слом, идея — одна огромная фраза |
| `text` | `hook`, `body`, `summary` («строка\nакцентная строка»), `summary_icon` | узнавание, объяснение + плашка-вывод |
| `steps` | `hook`, `steps: [{title, text}]` (до 4) | процесс, новое убеждение |
| `cards` | `hook`, `body`, `cards: [{title, text, icon}]` (2 или 4) | «из чего состоит», перечень |
| `compare` | `hook`, `body`, `columns`, `rows: [[было, стало], …]` (до 3) | пример, доказательство |

Общие: `label` (метка в шапке), `bg` (`dark`/`light` — только если нужно сломать чередование),
`header: false` (убрать шапку). Акцент — `[[слова]]`, полужирный — `**слова**`, перенос — `\n`.
Иконки: `chat`, `mic`, `alert`, `spark`, `play`, `search`, `doc`, `check`, `clock`, `gear`, `chart`,
`bolt`, `map`, `flask`, `question`, `image`, `arrow-right`, `arrow-down`.

Фото-слайд: текст не ложится на лицо. Заходит — `shift_x` (сдвиг кадра вправо, %) с `zoom` 1.05–1.15
и/или уже `text_width` (0.5–0.6). Строки заголовка короче — заголовок крупнее: слово-два на строку
на обложке и в `statement`.

## Картинки: что кодом, что генерацией

- **Сначала кодом**: схемы, шаги, карточки, сравнения, интерфейсы — это типы слайдов выше, генерация не нужна.
- **Генерация — только живые кадры**, реалистичные, без графики, 3D и надписей.
- Порядок: Codex по её подписке ChatGPT Plus (бесплатно) → кончился лимит или не сработал → kie.ai
  (платно, ключ `KIE_API_KEY`): кадр без неё — Grok Imagine 2.0 (запасная GPT Image 2.5);
  кадр с ней (`--ref`) — Nano Banana 2 в 2K (её выбор по сходству, 2026-09-25), запасная GPT Image 2.5.
  **Nano Banana 2 — самая дорогая: только для её внешности.**
- Не генерирую её «скрины», результаты, чужие интерфейсы и логотипы под видом настоящих.

## Обложка поста — по её референсам (2026-09-25)

Её слова: «обложки чередуем тёмная-светлая, с моим фото и просто с фото под пост подходящий по смыслу».
Эталон — её скилл `cover-post-katerina` (`essa-ai/visual_references/обложки на посты/`) и четыре референса
обложек («Что использовать в ChatGPT и когда», «Как попросить ChatGPT…», «Зачем объяснять ChatGPT цель…»,
«Как использовать примеры…»). Язык тот же, что у карусели: капс, фиолетовый акцент, line-иконки.

Приметы: плашка-таблетка с темой + линия + точка; огромный заголовок слева, ключевое слово фиолетовое;
рукописная мысль из поста терракотой (1–2 строки); подпись капсом с вертикальной чертой
(«ДЕТАЛИ / ИМЕЮТ / ЗНАЧЕНИЕ» или своя по смыслу); плитки с иконками (`icons`, до 3); тонкие дуги,
узлы, сетка точек; справа сверху «ТЕСТИРУЮ / АНАЛИЗИРУЮ / УЛУЧШАЮ» — только когда справа не её фото.

**Чередование:** светлая с её фото → тёмная с фото по смыслу → … Сборка сама помнит прошлую обложку
(`essa-ai/content/.last-cover.json`); `bg`/`photo_kind` в `cover.json` — только чтобы сломать очередь.
- её фото: генерация по `face-reference.jpg` на **гладком фоне цвета обложки** (светлая — очень светлый
  лавандовый, тёмная — графитовый), она справа, слева пусто — тогда фото сливается с фоном;
- фото по смыслу: реалистичный предметный кадр (Grok), объект справа, слева тёмное/светлое пустое место.

```text
.venv\Scripts\python.exe -m integrations.visuals.cover <папка комплекта> [cover.json]
```
`cover.json`: `hook` (`[[акцент]]`, 3–5 коротких строк), `pill`, `hand`, `support`, `icons`, `photo`,
`focus`, `name` (имя файла, по умолчанию `cover`). Образцы: `essa-ai/content/2026-09-25-golos-karusel/cover-light.json`,
`cover-dark.json`. Проверка глазами: ничего не налезает, текст не на лице, фото похоже на образец.
