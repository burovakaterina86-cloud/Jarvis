# carousel-instagram — картинки в её системе

Отвечаю за визуальную сборку: слайды карусели, обложка поста, фон сторис.
Стратегию, тему, факты и текст не придумываю — они приходят готовыми
(`content brief → slide functions → textwriter → humaniser → carousel-instagram`).
Утверждённый текст не переписываю: только разбивка на строки и акцентное слово.

## Источники правил

| Что | Файл |
|---|---|
| дизайн-система каруселей — главный источник | `essa-ai/ESSA_PRESENTATION_STYLE.md` (раньше `18_CAROUSEL_VISUAL_SYSTEM.md`) |
| общий бренд, обложка поста, сторис | `essa-ai/DESIGN.md` (§18 — сторис), `essa-ai/POST_COVERS.md` |
| смысловой маршрут и стоп-условия | `essa-ai/SKILL_carousel-instagram.md` §13, §19, §20 |
| образец storyboard | `essa-ai/content/2026-09-23-7-priznakov/storyboard.md` |

Ссылаюсь на `ESSA_PRESENTATION_STYLE.md` по разделам: §1 формат, §3 цвет, §4 заголовок,
§5 второй уровень, §6 рукописные, §7 верхняя панель, §8 композиции A–E, §9 фото,
§10 свет, §11 глубина, §12 иконки, §13 плашки, §14 декор (никаких blobs), §17 ритм,
§18 обложка, §19 финальный слайд, §20 ключевой принцип. Цвета, поля и плашки уже
в коде — `tokens.CAROUSEL_PALETTE`, `tokens.CAROUSEL_MARGIN`, `tokens.PLATE`,
оранжевый `tokens.ACCENT["ORANGE_ACCENT"]`; значения не выдумываю и в разметке не правлю.

Стили — только `STYLE_01`, `STYLE_02_LIGHT`, `STYLE_02_DARK`; `STYLE_03` и новые нет.
Порядок тёмных и светлых задаётся один раз на карусель: `tokens.alternating_styles`.
Шрифты — Roboto Condensed + Open Sans, пометки — `Marck Script`.
Третий фирменный шрифт без её решения не ввожу.

## Порядок работы — её слова

1. проанализируй смысл;
2. разбей материал на слайды;
3. придумай отдельную визуальную метафору для каждого слайда;
4. составь storyboard;
5. проверь, чтобы композиции и визуальные объекты не повторялись.

Для каждого слайда — её вопрос:
«какой кадр или объект лучше всего показывает эту мысль без текста?»

Storyboard сохраняю файлом `storyboard.md` в папку комплекта — как в образце: главная мысль,
метафора, тип композиции, строки заголовка, акцентное слово, пометка, материалы; в конце
таблица «соседний тип совпадает?».

## Сборка — одна команда

Данные слайдов кладу в `<папка комплекта>/slides.json` и собираю:

```text
.venv\Scripts\python.exe -m integrations.visuals.build <папка комплекта> [slides.json]
```

Формат: `{"slides": [{…поля слайда…}, …], "background": "dark"|"alternate", "cover": {…}?, "story": {…}?}`.
Фон — по её словам в запросе: «чередовать» → `"alternate"` (`alternating_styles`), «в тёмной» → `"dark"`; не сказала — тёмный.
`cover` — `hook`, `subtitle`; `story` — `key_phrase`, `caption`: обложка и фон сторис собираются той же командой.
Относительные пути к файлам считаются от папки `slides.json`.
Выход — `visuals/carousel-01.png …` и одноимённые `.html`, отчёт `kit.report` в консоль.
Код выхода не 0 — картинок нет (3 — PNG не сняты, 2 — ошибка данных): так владелице и говорю, «готово» не пишу.
Правка одного слова — правлю `slides.json` и запускаю ту же команду; из HTML данные
не восстанавливаю. Внутри — `kit.build_kit_visuals` и `render.render_image`.
Выход обложки и сторис — `visuals/cover.png` и `visuals/story.png`.

## Поля слайда

Ровно то, что принимает `templates.build_carousel_slide`. `index`, `total`, `notes`
ставит сборка.

| Поле | Что делает | Пример |
|---|---|---|
| `hook` | заголовок; `\n` — перенос строки | `"1. У тебя куча\nсохранённого"` |
| `accent_word` | слово или список слов заголовка оранжевым (§4); нет — заголовок белый | `"сохранённого"` |
| `label` | рубрика в шапке `02 / 09 ── ПРИЗНАК 1` (§7); служебные функции слайда в кадр не идут | `"Признак 1"` |
| `header` | верхняя панель; `false` на обложке (§18) | `false` |
| `body` | текст второго уровня (§5), слева | `"Промты. Гайды.\nНо когда нужно…"` |
| `role` | `cover` — крупный хук; иначе `slide` (сборка ставит сама) | `"cover"` |
| `style` | стиль одного слайда поверх режима фона | `"STYLE_01"` |
| `composition` | тип §8: A фото, B устройство, C схема, D UI-хаос, E типографика; нет — выводится из данных | `"E"` |
| `summary` | плашка-сноска: строка белая `\n` строка сиреневая (§13) | `"Вроде помогла.\nНо ручная работа осталась."` |
| `summary_accent` | оранжевая обводка плашки-вывода | `true` |
| `handwritten` | рукописные пометки `hand-note` со стрелкой; строка, список или `{"text","at"}` | `["подписка ≠ польза", "встроить в процесс"]` |
| `steps` | цепочка кружков с номерами, оранжевые отрезки `step-link` | `[{"caption": "текст"}, {"caption": "монтаж"}]` |
| `flow` | поток карточек с рисованными стрелками, последняя залита | `[{"title": "сценарий"}, {"title": "публикация"}]` |
| `cards` | сетка карточек с иконками, акцентная обведена | `[{"title": "промты"}, {"title": "гайды"}]` |
| `chain` | вертикальная цепочка сверху вниз (§19, финал) | `[{"title": "что можно убрать"}, …]` |
| `screenshot` | её скрин внутри корпуса устройства, в перспективе (§8 B) | `"visuals/phone-home.webp"` |
| `device` | корпус для `screenshot`: `laptop` или `phone` | `"phone"` |
| `screens` | один-три её скрина правой сцены, каждый внутри корпуса устройства, в перспективе (§8 D); элемент может быть `{"src","device"}` | `["visuals/files-list.png"]` |
| `ui_cards` | §8 D UI-хаос: карточки рисует вёрстка (плашка, иконка, строка) — подписи из слов её слайда, не скрины; строка или `{"title","icon","active"}`, активная (по умолчанию средняя) в оранжевой обводке | `[{"title": "Промты", "icon": "doc"}, "Гайды"]` |
| `apps` | число плиток приложений в телефоне вместо скрина | `16` |
| `photo` | её портрет (§8 A, §9), фон снят заранее | `"visuals/katerina-portrait-cutout.png"` |
| `portrait_width` | доля кадра под портрет, 0.40–0.55 | `0.40` |
| `footer_thesis` | строка тезиса в подвале | `"процесс важнее инструмента"` |
| `thesis` | не рисуется (она отменила тезис в шапке); не заполняю | — |

`steps`/`flow`/`cards` не переданы — вёрстка соберёт их из `body` по её разделителям:
`→` поток, `·` сетка, «1. … 2. …» шаги. Своих смыслов не добавляю.

## Материалы владелицы

- Портреты и скрины — `essa-ai/photo/` и `essa-ai/photo/screens/`. Путь даю в данных слайда,
  сборка копирует файл в `visuals/`. Портрет без фона — `cutout.make_cutout`,
  исходник не трогаю.
- Скрин владелицы размывается по умолчанию (`tokens.SCREEN_BLUR`); не размывать —
  только если она сама так сказала, и перед сборкой предупреди её, что скрин станет
  читаемым (`"blur": false` в `screens`/`screenshot`, для каждого скрина отдельно).
  Её фото не размывается никогда.
- Нет её кадра под метафору — сначала спрашиваю, есть ли у неё такой; нет — генерирую
  (её решение 2026-09-25), одной командой на картинку:
  `.venv/Scripts/python -m integrations.visuals.imagegen "промпт" <папка>/visuals/<имя>.png --ratio 4:5`
  Сначала рисует Codex по её подписке ChatGPT Plus, кончился лимит или не сработал — сам уходит
  на kie.ai (платно, ключ `KIE_API_KEY`): без человека её внешности — Grok Imagine 2.0; с ней — `--ref <её фото>`,
  тогда GPT Image 2.5 или Nano Banana 2 в 2K. Кто нарисовал — в выводе;
  в ответе ей пишу, если был kie.ai. Только реалистичные живые фотокадры, не графика и не иллюстрация.
  Готовую картинку ставлю в `screenshot`/`screens` (внутри устройства, `"blur": false` — это не её скрин)
  или в `photo` (композиция A). Надписей на картинке не заказываю — текст ставит вёрстка.
- Нужен новый кадр с ней — только `--ref essa-ai/photo/portraits/face-reference.jpg` (её решение
  2026-09-25): одежду, позу, причёску, ракурс меняю; внешность и черты лица сохраняю, возраст не добавляю.
  Готовый кадр сравниваю с образцом глазами, непохожа — перегенерирую.
  Не генерирую: её «скрины» и результаты, чужие логотипы и интерфейсы под видом настоящих.
  Одна карусель — один свет и настроение кадров (одни и те же слова о свете в каждом промпте).
- Файла нет — слайд соберётся без него, строка об этом будет в отчёте.

## Рукописные пометки

Пишутся отдельно от текста слайда через `textwriter` → `humaniser` (или даёт владелица):
два-три слова, комментарий сбоку, а не пересказ. Пометку, повторяющую заголовок или
лид, вёрстка не нарисует. Нет поля — нет пометок.

## Проверка перед выдачей

- открыл каждый PNG глазами, а не только отчёт;
- типы композиции чередуются, соседние не совпадают (таблица в storyboard);
- плашка и текст не пересекают портрет;
- слова не рвутся, текст не обрезан, мелкого текста нет;
- акцент — одно-два слова, текст владелицы не изменён;
- снимок не получился — так и говорю и отдаю HTML; render, которого не было, не заявляю.

Рендер: `render_image` снимает питоновским Playwright. Нет его — возвращает `mcp_plan`:
страницу раздаю `render.serve()` (`file:` заблокирован), снимаю
`browser_take_screenshot` с `target: div.canvas`, PNG — внутри папки проекта.
Нет сети до Google Fonts — в отчёте предупреждение, кадр только черновой.

## Границы

Ничего не публикую и не отправляю. Выдача — PNG в `<папка комплекта>/visuals/`
