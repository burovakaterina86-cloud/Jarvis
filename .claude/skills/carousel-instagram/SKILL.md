# carousel-instagram — картинки в её системе

Перенос её адаптера `essa-ai/SKILL_carousel-instagram.md`. Тот файл остаётся
источником истины: спорные места смотри там, здесь — рабочий порядок.

## Роль

Отвечаю за визуальную сборку: слайды карусели, обложка поста, фон сторис.
Не отвечаю за стратегию, тему и факты — они приходят готовыми.

Главное правило (§21): оптимизирую не под «сделать красивее любой ценой»,
а под «сделать смысл понятнее, удержать психологический переход и оформить
это в узнаваемой системе Катерины».

## Обязательный порядок текста (§4)

```text
content brief → slide functions → textwriter → humaniser
→ VOICE / BRAND_VOICE preflight → carousel-instagram
```

Текст ко мне приходит уже после `textwriter` и `humaniser`.
`textwriter` и `humaniser` не меняют FUNNEL_STAGE, FUNCTION, BELIEF_BEFORE,
BELIEF_AFTER, MAIN_IDEA, PROOF, NEXT_STEP, CTA и доказательный статус.

Если владелица дала утверждённый текст слайдов — заново его не переписываю.
Допустимы только минимальные layout-правки; сокращение — без изменения смысла.

## Источники перед production (§3)

Читаю адресно, не целиком:

| фон сторис | `essa-ai/DESIGN.md` §18 «REELS — VISUAL SYSTEM» | 1080×1920 |

Общая основа — `DESIGN.md`: 12 цветов core palette и три начертания.
Её примеры: `essa-ai/visual_references/карусель стиль 1`, `карусель стиль 2`,
`обложки на посты`, плюс `CAROUSEL_ASSETS.md` и `VISUAL_REFERENCES.md`.
Готовая её вёрстка — `essa-ai/visual_references/design-code-studio_essa_ai-v1.html`.

Цвета, шрифты и размеры не выдумываю: они зашиты в `integrations/visuals/tokens.py`
ровно по её файлам. Обновился `DESIGN.md` — правится `tokens.py`, а не разметка.

## Стили (§5–§6)

Только `STYLE_01`, `STYLE_02_LIGHT`, `STYLE_02_DARK`. `STYLE_03/04/05` и новые
style-ID — нет.

- PROCESS / SYSTEM / WORKFLOW / MAP / LEVELS → `STYLE_01`
- POSITIONING / STORY / OBSERVATION / EXPLANATION / BELIEF SHIFT → `STYLE_02_LIGHT`
- тёмная editorial-версия — только по прямой просьбе → `STYLE_02_DARK`

По умолчанию для editorial — `STYLE_02_LIGHT`. Тёмный не беру «потому что эффектнее».

## Как рисую (§17)

Картиночной модели нет и не нужно. Её родной способ: HTML/CSS + Playwright.

1. Текст слайдов → вёрстка: `integrations.visuals.templates`
   (`build_carousel_slide`, `build_post_cover`, `build_story_background`).
2. Снимок: `integrations.visuals.render.render_image(html_path, out_png, width, height)` —
   единственная точка снимка в проекте.
3. PNG ложится в `<папка комплекта>/visuals/` рядом с текстами.

Весь комплект одной командой:

```python
from integrations.visuals import kit
items = kit.build_kit_visuals(
    kit_dir,
    carousel_slides=[{"hook": "...", "body": "...", "label": "...", "role": "cover"}],
    cover={"hook": "...", "subtitle": "..."},
    story={"key_phrase": "..."},
    style="STYLE_02_LIGHT",
)
print(kit.report(items))
```

Имена предсказуемые: `carousel-01.png`, `carousel-02.png`, …, `cover.png`, `story.png`,
рядом одноимённые `.html`.

## Плотность слайда — её эталон

Она прислала четыре своих слайда (2026-09-21) и сказала: «много воздуха, не хватает
плашек, стрелок, иконок». Пустой слайд — дефект. Зоны каждого слайда:

```text
шапка `NN | РУБРИКА` + тезис капсом справа
заголовок (2 строки: первая обычная, вторая акцентом)
подзаголовок
тело с графикой
нижняя плашка-итог: иконка-молния + строка капсом через →
подвал: тезис мелким капсом слева, `NN/NN` справа
```

Поля `build_carousel_slide`: `thesis`, `footer_thesis`, `summary`, `steps`, `flow`,
`cards`, `handwritten`, `photo`, `screenshot`.

- `steps` — цепочка шагов: кружки с номерами на линии, иконка, жирная подпись,
  тонкое пояснение (`{"caption", "note", "icon"}`);
- `flow` — поток карточек со стрелками `→`, последняя залита акцентом;
- `cards` — сетка карточек со скруглением;
- блоки не переданы — собираю их из текста слайда: `→` даёт поток, `·` — сетку,
  «1. … 2. …» — цепочку. Своих смыслов не добавляю.

Иконки — inline SVG из `templates.ICONS`, простые line-icons (DESIGN.md §15).
Внешних картинок и иконочных шрифтов нет.

## Рукописная строка, фото и скриншоты

`handwritten` — одна строка-подпись шрифтом `Marck Script` (её собственное решение,
подтверждено 2026-09-21; текстовым шрифтом системы он не становится). Ставится только
на первом и последнем слайде — на остальных не ставлю, даже если передали.

`photo` и `screenshot` — файлы владелицы. Сам ничего не генерирую и чужого не
подставляю: файла нет — слайд собирается без него, а в `notes` (и в `kit.report`)
ложится строка об этом. Портрет встаёт справа и растворяется в фоне маской-градиентом;
скриншот — блоком со скруглением и свечением, `object-fit: contain`, без обрезки.

## Чередование стилей

Порядок задаётся один раз на всю карусель: `tokens.alternating_styles(total)` —
тёмный и светлый попеременно, первый и последний тёмные (это слайды с её фото).
`kit.build_kit_visuals` без `style` берёт именно его; вручную стиль на каждый слайд
не подбираю.

## Служебные пометки не попадают в кадр

Функция слайда («внимание», «новое убеждение», `CTA`) — внутренняя пометка.
В рубрику шапки идёт только слово владелицы; дала функцию — рубрики просто нет
(`templates.SERVICE_MARKS`).

Питоновского пакета `playwright` в `.venv` нет, и ставить его не надо: браузер
подключён как MCP-сервер. Тогда `render_image` возвращает `ok=False` и готовый
`mcp_plan`, который я выполняю сам. Две особенности MCP-браузера проверены на живом
прогоне и учтены в плане:

- протокол `file:` заблокирован — вёрстку раздаю локально:
  `with render.serve(kit_dir / "visuals") as base:` и иду на `base/имя.html`;
- окно браузера не масштабируется, `browser_resize` на кадр не влияет — поэтому
  снимаю не вьюпорт, а сам холст: `browser_take_screenshot` с `target: div.canvas`.
  Размер холста задан в CSS и от окна не зависит;
- путь PNG должен лежать внутри папки проекта, наружу браузер не пишет.

Вёрстка при этом уже на диске, тексты комплекта не теряются.

Не заявляю render, которого не было (§20). Если снимок не получился — так и говорю
и отдаю HTML.

## Шрифты

`Roboto Condensed Bold` (заголовки), `Open Sans Regular` (текст),
`Open Sans SemiBold` (подзаголовки и labels). Третий фирменный шрифт вводить нельзя
без отдельного решения владелицы.

На машине они не установлены — подключаются с Google Fonts при рендере. Нет сети:
`render_image` кладёт в `warnings` строку о том, какие шрифты не загрузились и что
браузер подставит `sans-serif`. Такой кадр годится для черновой проверки, не для
публикации — говорю об этом владелице.

## Технические инварианты (§11)

- карусель и обложка `1080 × 1350`, сторис `1080 × 1920`;
- safe zone `72–88 px`, базовый ориентир `80 px`;
- hook `88–120 px`, заголовок слайда `60–84 px`, body `34–42 px`,
  label `24–30 px`, микротекст не мельче `22–24 px`;
- no clipping, no overflow, текста за safe zone нет;
- важную информацию не уменьшаю ради вмещения — сначала сокращаю текст;
- одна визуальная система на всю карусель.

## Смысловой маршрут (§13)

```text
HOOK → IDENTIFICATION → PROBLEM → CONFLICT → PATTERN INTERRUPT
→ NEW BELIEF → MECHANISM / PROOF → BRAND IDEA → CTA
```

Количество слайдов меняется. Нельзя: убрать ключевой переход, переставить
смысловые блоки ради дизайна, продать раньше, придумать proof, усилить case,
изменить CTA.

## Обложка поста

Один сильный тезис + один главный визуальный акцент. `STYLE_02_LIGHT`:
светлый lavender-фон, graphite-текст, один violet-акцент, много воздуха.
Hook слева, место под фото справа — фото подставляет владелица; заголовок
не обрезаю, не помещается — сокращаю текст, а не уменьшаю шрифт.
Фирменные элементы: pill `МОЙ ПОДХОД`, тонкая линия рядом, microtext
`ТЕСТИРУЮ / АНАЛИЗИРУЮ / УЛУЧШАЮ`. Лицо текстом не закрываю.

Не делаю: длинный подзаголовок на шесть строк, много иконок, пять цветов,
3D ради 3D, длинный CTA на обложке.

## Фон сторис

`DESIGN.md` §18: крупный текст, одно сообщение на сцену, один key phrase.
Палитра — graphite, white, violet, lavender. Не использую постоянный glossy 3D,
мелкие captions, визуальный шум, случайный multi-color neon.

## Проверка перед выдачей (§19)

Стратегия: FUNNEL_STAGE, FUNCTION, BELIEF_BEFORE → BELIEF_AFTER, MAIN_IDEA, CTA
сохранены; PROOF не усилен.
Текст: pipeline пройден, VOICE соблюдён, выдуманных фактов нет.
Дизайн: активный style-mode, `Roboto Condensed + Open Sans`, core palette из
`DESIGN.md`, нет yellow/orange core-accent, safe zone соблюдена, hook считывается
первым, все слайды — одна система.
Ритм: карусель просмотрена целиком; соседние слайды не повторяют одну dominant
композицию без причины; BRAND IDEA и CTA различаются визуально.

## Стоп-условия (§20)

Останавливаюсь и правлю до выдачи, если: текст механически уменьшен до мелкого;
CTA изменён; proof усилен; добавлен новый кейс; style-mode не активен; появился
yellow/orange core-accent без прямой просьбы; карусель выглядит набором разных
шаблонов; заявлен render, которого не было.
