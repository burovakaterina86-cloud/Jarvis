# Изображения и видео через Vels Visual

## Подключить актуальный маршрут

Перед генерацией найди и прочитай доступный скилл `visual`. Он задаёт текущие команды Vels Visual, выбор моделей и правила расходов. Здесь хранится процесс работы с сайтом, а не копия каталога моделей или цен.

Если `visual` или CLI недоступны, продолжай сборку на имеющихся материалах и явно обозначь зависимость. Названного пользователем провайдера изображений сохраняй; для другого доступного генератора следуй его правилам. Видео в этом процессе создаётся через Vels Visual.

Сначала проверь журнал и готовые результаты: возможно, нужный запрос уже выполнен или ещё работает. Сохраняй `taskId`, `api`, параметры, оценку стоимости, статус и локальные файлы. Ключей в журнале быть не должно.

## Модель, параметры, бюджет

Команды ниже — последовательность подготовки. Подставляй фактические значения, подтверждённые текущим CLI:

```bash
velsvisual models --refresh --json
velsvisual recommend video --json
velsvisual schema <model> --json
velsvisual pricing --search <model> --json
velsvisual credits --json
```

Реестр обновляй один раз за сессию. Если модель уже выбрана пользователем, сохраняй её; иначе предложи подходящие актуальные варианты по правилам `visual`. Для изображений используется категория `image`.

Проверь соотношение сторон, длительность, разрешение, поля исходных изображений, число результатов и звук. Не соединяй взаимоисключающие режимы и не угадывай поля. Оценка должна покрывать всю партию A/B/C или всю цепочку клипов, а не только один результат.

До реального запуска сообщи модель, параметры и оценку стоимости. Применяй правила подтверждения расходов из актуального `visual`. Ранее разрешённый конкретный запуск или бюджет удовлетворяют соответствующему пункту проверки `visual`, если покрывают те же действия, параметры и актуальную цену; повторное согласование не требуется. Выбор изображения сам по себе не разрешает оплату видео.

Совет о дешёвой пробной генерации не добавляет разрешения на новый запуск и не заменяет согласованную модель. Реальная черновая генерация должна входить в поручение и бюджет. Для проверки сборки запроса используй `--dry-run`.

Проверь собранный запрос через `--dry-run --json`. Свежесть схемы и цены должна быть подтверждена; старая запись кэша не заменяет недоступный источник. Если команда получила свежие данные, но не смогла записать кэш, допустимо проверить публичную официальную схему в режиме чтения. При неизвестной цене согласуй неопределённость до расходов, при неизвестных полях останови только генерацию.

## Изображения A/B/C

Когда главный визуал создаётся с нуля, подготовь по умолчанию три отдельных готовых изображения. Различай свет, пространство, масштаб или композицию, сохраняя предмет и ограничения бренда. Три промпта или один коллаж не заменяют три результата.

Покажи файлы, сравни их пользу для выбранного движения и получи выбор. Утверждённый кадр пользователя используется сразу; другое явно заданное количество имеет приоритет. Не отправляй все варианты в видеогенерацию. Исправляй выбранный кадр до создания ролика.

Передавай только относящиеся к задаче разрешённые референсы. Проверяй реальные размеры, прозрачность, края и кадрирование. Текст интерфейса добавляется в HTML, а не впечатывается в изображение.

## Видео и продолжение после прерывания

Составь промпт по последнему выбранному кадру и партитуре: неизменяемый предмет, движение камеры или деталей, свет, начальное и конечное состояния, место под текст, ограничения на деформации, мерцание, тряску и склейки. Для перемотки по скроллу задавай отсутствие звука под полем, которое действительно есть в схеме модели.

```bash
velsvisual run <model> --prompt <prompt> --image <selected-image> --json
# Сразу сохранить taskId, api и фактические параметры.
velsvisual wait <taskId> --api <api> --timeout 900 --json
velsvisual download <returned-url> -o <output-file> --json
```

Добавь нужные параметры через подтверждённые поля модели. Допустим запуск с ожиданием и скачиванием, если идентификатор сохраняется и прерывание не теряет задачу. Ожидание организуй так, чтобы можно было сообщать пользователю прогресс.

При неоднозначном ответе сначала проверь существующую задачу. Если ответ потерян до получения `taskId`, запиши время, модель и хеш запроса без секретов, проверь доступную историю и существующие журналы. Не изобретай команду поиска истории без идентификатора. Если исход не восстановлен, запроси сведения из истории провайдера; новый платный запуск требует осознанного разрешения с учётом возможного двойного списания. Продолжай независимую работу с сайтом.

Повторная генерация из-за неудачного результата тоже расходует кредиты. Сохраняй каждый результат отдельно. Временный URL не является готовым артефактом: скачай файл и проверь его.

## Подготовка доставляемого видео

Исходник и версия для сайта хранятся раздельно. Для локального H.264 с частыми ключевыми кадрами, без звука и B-кадров используй:

```bash
python .claude/skills/site-builder/scripts/prepare_video.py <source.mp4> <assets/film.mp4> --max-edge 1280 --gop 4
```

Скрипт требует работающие FFmpeg и FFprobe. Проверь `--help`; при необходимости задай пути через `--ffmpeg`/`--ffprobe` или `SITE_BUILDER_FFMPEG`/`SITE_BUILDER_FFPROBE`.

Скрипт ограничивает размер и частоту кадров без увеличения исходного разрешения, добавляет `faststart`, создаёт `.poster.jpg` из доставляемого ролика и `.media.json` с результатами проверки. Существующие файлы не перезаписывает. `--inspect` показывает метаданные без перекодирования. Он не создаёт медиа через API и не исправляет плохую постановку.

Проверь первый, промежуточные и последний кадры, геометрию предмета и места под текст. Для цепочки сравни стыки после финального кодирования; следующий старт может быть кадром конца предыдущего ролика. Не замыкай каждое путешествие на одну исходную картинку, если камера должна идти вперёд.

Фактическую стоимость указывай по подтверждённому учёту задачи. Разница общего баланса при параллельных запросах не доказывает цену конкретного ролика.
