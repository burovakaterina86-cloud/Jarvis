# Комплектный движок: API и ограничения

Читай этот справочник только при выборе `vendor/scroll-engine/`. Это автономный сторонний JavaScript и CSS без npm-зависимостей. Старые серверы, генераторы, реестр проектов и HTML-шаблоны ему не нужны. Страницу и медиа создаёт агент; движок читает готовую разметку и управляет её состоянием.

## Подключение

Движок кладёт в сайт команда `python -m integrations.site_builder init <имя>` (файлы окажутся в `outbox/sites/<имя>/scroll-engine/`). Подключи CSS до отрисовки страницы, а JavaScript — после разметки. Файла уведомлений о сторонних материалах в наборе нет: см. примечание в `SKILL.md`.

```html
<link rel="stylesheet" href="site-builder.css">
<section data-sc-act="scrub" data-sc-span="2.6" data-sc-dwell="0.35">
  <div data-sc-stage>
    <img class="sc-stage__poster" src="assets/film.poster.jpg" alt="Описание сцены">
    <video data-sc-scrub data-sc-src="assets/film.mp4" playsinline muted></video>
    <div class="sc-scrim" aria-hidden="true"></div>
    <div class="sc-copy sc-copy--lead">
      <h1 data-sc-cue="0 0.7 0 0.2" data-sc-kinetic="lines">Настоящий заголовок</h1>
    </div>
  </div>
</section>
<script src="site-builder.js"></script>
<script>
  const scene = SiteBuilder.mount(document.body);
</script>
```

Вызывай `mount` один раз на жизнь страницы, после появления нужного DOM. Передавай контейнер, содержащий акты или путешествие: сам переданный корневой элемент в поиск не включается. Допустим существующий CSS-селектор; несуществующий приведёт к ошибке.

Возвращаются `layout()`, `read()`, массивы `acts`, `worlds`, `clips` и значение `lerp`. `layout()` пересчитывает размеры уже найденных элементов, а не собирает новый DOM. `SiteBuilder.instances` полезен для диагностики. Метка `html.sc-ready` означает завершение первоначального монтирования, а не готовность видео или шрифтов.

Метода снятия движка нет. Повторный `mount` добавляет слушатели и циклы отрисовки. Для приложения со сменой страниц без перезагрузки используй механизм с подходящим жизненным циклом или отдельную адаптацию; одного повторного `layout()` для новых узлов недостаточно.

## Акты, текст и приёмы

`data-sc-act` принимает `scrub`, `pin`, `pan` либо `flow`. Первые три закрепляют сцену, а `flow` остаётся в обычном потоке. Для закреплённого акта нужен дочерний `[data-sc-stage]` или `.sc-stage` с `position: sticky`; не переопределяй это позиционирование случайным стилем страницы.

`data-sc-span` — полная высота акта в высотах окна, по умолчанию 1,5. Например, `2.6` даёт около 1,6 высоты окна хода закрепления. Значения больше 0, но не больше 1 схлопывают ход в 1 пиксель; `0` заменяется значением по умолчанию. Для короткой незакреплённой секции выбирай `flow`.

Каждый акт публикует `--sc-p` от 0 до 1 после преобразования задержкой `data-sc-dwell`. Код ограничивает `dwell` диапазоном 0–1; для спокойного удержания начинай с умеренных значений и проверяй эффект на кадрах.

| Атрибут | Назначение и существенное условие |
| --- | --- |
| `data-sc-cue="from [to [rampIn [rampOut]]]"` | Появление, полная видимость и уход реплики. Рампы — доли её окна, по умолчанию по 0,3. Для плато сумма рамп меньше 1. Одна цифра означает вход длиной 0,18 прогресса акта и дальнейшее удержание. |
| `data-sc-kinetic="lines"` | Сборка по строкам; также доступны `words` и `chars`. Атрибут должен стоять на том же элементе, что и `data-sc-cue`, как в примере выше. |
| `data-sc-pan="0"` | Горизонтальный ход ровно на ширину переполнения относительно окна. Положительное значение увеличивает ход: `0.08` добавляет 8%, а не задержку старта. Без переполнения лента не движется. |
| `data-sc-reveal="up"` | Раскрытие маской; также `down`, `left`, `right`, `iris`. Окно задаётся `data-sc-reveal-at`. Проверяй края букв и маску обёртки. |
| `data-sc-parallax="-0.2"` | Смещение слоя в зависимости от прогресса и высоты окна. Значение выбирается по композиции. |
| `data-sc-count="0 4200"` | Счётчик проверенного числа; пример не является разрешением придумывать показатели. Вне акта срабатывает при входе, длительность задаётся `data-sc-count-ms`. |
| `data-sc-in` | Однократное появление элемента обычного потока; последовательную задержку задаёт `data-sc-stagger`. |
| `data-sc-tilt`, `data-sc-magnet`, `data-sc-spotlight` | Наклон, притяжение и подсветка для подходящего указателя. Подсветка публикует координаты `--sc-mx` и `--sc-my` от 0 до 1. |
| `data-sc-drift="#161210"` | Переход фона страницы к указанному цвету. Основные переменные темы: `--sc-canvas`, `--sc-surface`, `--sc-ink`, `--sc-ink-soft`, `--sc-accent`, `--sc-accent-ink`. |
| `data-sc-sequence="frames/{i}.webp:120:1"` | Последовательность изображений на `canvas`: шаблон пути, число кадров, начальный индекс. Учитывай общий объём загрузки и отдельное поведение при сокращении движения. |

Текстовые реплики перезаписывают свой `transform`. Даже `data-sc-rise="0"` убирает только подъём, а не саму запись преобразования. Независимое движение назначай обёртке. Видимость реплики не гарантирует правильный клавиатурный фокус; проверь скрытые кнопки и переходы к ним.

## Видео

Внутри акта используется первое `video[data-sc-scrub]`. Для управляемой загрузки задавай `data-sc-src`, при необходимости `data-sc-src-mobile`, без обычного `src` и вложенного `<source>`. Иначе браузер может запросить видео самостоятельно ещё до логики движка.

Движок получает весь файл через `fetch` как `Blob`, поэтому нужен доступный HTTP(S)-источник и корректный CORS. Мобильный вариант выбирается при загрузке: грубый указатель или ширина не больше 860 пикселей. Последующее изменение ширины не заменяет уже загруженный клип.

У закреплённого акта видео по умолчанию проходит всю видимую жизнь сцены, включая вход и выход в пределах доступной прокрутки. `data-sc-clip-map="travel"` связывает его только с ходом закрепления. Текст и видео имеют отдельные значения прогресса; проверяй их согласованность на реальной странице.

Сглаживание берётся из `data-sc-lerp` на видео, затем корневом элементе, `<html>`, параметре `opts.lerp` и наконец из значения 0,18. Положительные значения ограничены 0,02–1; ноль означает переход к следующему источнику. Зона нечувствительности — 8 мс на компьютере и 20 мс на телефоне. Новый переход не назначается во время незавершённой перемотки; край времени ограничен 0,999 длительности.

У текущей версии есть ограничения, которые нужно учитывать при приёмке:

- `sc-has-clip` может выставляться после `seeked` или таймера 2500 мс. Это не доказательство реально нарисованного кадра; проверь постер и декодирование отдельно, при необходимости добавь адаптацию страницы.
- Цикл `requestAnimationFrame` продолжает работать постоянно; пропускаются ненужные записи времени. Не обещай полную остановку движка после остановки прокрутки.
- Созданные `Blob` URL не освобождаются движком. Учитывай объём клипов и жизненный цикл страницы.
- Предпочтение сокращённого движения считывается JavaScript один раз при загрузке. В этом режиме видео не запрашивается, но последовательность изображений имеет отдельную загрузку. Для проверки изменения настройки перезагрузи страницу и проверь резервные состояния.

## Непрерывное путешествие

```html
<div data-sc-mode="worldflight" data-sc-seam="0.12" data-sc-lerp="0.12">
  <div data-sc-world>
    <div data-sc-segment data-sc-w="1.3" data-sc-waypoint="Начало">
      <img class="sc-world__poster" src="assets/start.jpg" alt="Начальная точка">
      <video data-sc-src="assets/leg1.mp4"></video>
    </div>
    <div data-sc-segment data-sc-w="1.3" data-sc-waypoint="Прибытие">
      <img class="sc-world__poster" src="assets/end.jpg" alt="Конечная точка">
      <video data-sc-src="assets/leg2.mp4"></video>
    </div>
  </div>
  <div data-sc-world-copy>
    <div class="sc-world__scrim sc-scrim sc-scrim--band" aria-hidden="true"></div>
    <div data-sc-copy data-sc-window="hero">Начальная мысль</div>
    <div data-sc-copy data-sc-window="0.35 0.65">Мысль на маршруте</div>
    <div data-sc-copy data-sc-window="finale">Итог и действие</div>
  </div>
  <div data-sc-spacer aria-hidden="true"></div>
</div>
```

Это пример двух участков, а не обязательная длина истории. Здесь нужны одна сцена `[data-sc-world]`, постоянный слой текста `[data-sc-world-copy]` и распорка `[data-sc-spacer]`. Сегменты находятся внутри сцены. После разметки достаточно одного `SiteBuilder.mount(document.body)` на всю страницу.

- `data-sc-w` — положительный вес участка в высотах окна, по умолчанию 1,3. Высота распорки равна `(сумма весов + 1) × innerHeight` в пикселях. Нужны ненулевые размеры при монтировании.
- `data-sc-linger` — задержка движения внутри участка, 0–0,6. Согласуй отношение веса к длительности соседних клипов.
- `data-sc-seam` — ширина стыка в высотах окна, по умолчанию 0,12. Положительные значения ограничены 0,02–0,4; ноль возвращает значение по умолчанию. Слишком короткие участки проверяй особенно внимательно.
- `data-sc-window` задаётся относительно всего пути: `hero` виден с начала, `finale` удерживается в конце, `from to [in [out]]` даёт числовое окно с плато. Одна цифра здесь создаёт короткое окно длиной 0,18, а не удержание до конца, как у обычного `cue`.
- Входящий сегмент проявляется поверх непрозрачного исходящего. Все ролики остаются смонтированными, `src` на границе не меняется.

`--sc-seg` содержит индекс участка с нуля, `--sc-segp` — его локальный прогресс до задержки. Событие `sc:waypoint` содержит `{index, count, label, el, progress}`; `progress` относится ко всему пути. Для получения начального события подпишись до `mount`. Навигацию по этим данным создаёт страница.

После интеграции выполни [проверку сайта](verification.md), включая промежуточные кадры, обратный ход и реальные действия. Наличие перечисленного API не заменяет проверку конкретной композиции.
