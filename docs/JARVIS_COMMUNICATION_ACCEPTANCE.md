# Приёмка исправлений общения JARVIS

Ветка `codex/jarvis-communication-repair`, исходный коммит `b3b3810`. Каждый этап отправляется отдельным коммитом. Подробности и решения: `JARVIS_REPAIR_PROGRESS.md`.

## Автоматические проверки

- Сквозной офлайн сценарий: CLI → HTTP Approvals → Telegram-карточка → «зачем?» → копия карточки → стоп. Дополнительный ход по копии не запускается.
- Проверены очереди, поздняя кнопка, ревью, Codex/Claude2, фоновые запросы, альбом, Python-обработчик и позднее письмо. Все данные тестов временные.
- `check_context_size.py`: корневые файлы 10.27/12 KB, SOUL 1.99/2 KB; правила 15.16 KB. Это байты файлов, не полный замер токенов CLI/MCP.
- `sync_mirrors.py --check`: совпадают.
- `check_hooks.py`: все случаи прошли; скрипт сам копирует хуки и политику во временный корень. Живые журналы не использованы для записи.
- Независимый обзор: шесть первичных замечаний и два последующих устранены. Последняя точечная проверка reviewer — 25 passed, новых существенных замечаний нет.
- Полный pytest для окончательного дерева: **1686 passed in 185.81s**. Предыдущий полный прогон — 1684 passed; после него добавлены две регрессии последних замечаний.
- Дополнительные ходы модели на простое объяснение разрешения отсутствуют (сквозной тест проверяет один запуск CLI). Живую стоимость и литературное качество реальной модели не измеряли.

## Живая проверка — ещё не выполнена

После контролируемого перезапуска одного экземпляра бота проверить:

1. «Посмотри идеи в контент-плане»: понятный ответ, без произвольного Python.
2. «Зачем тебе это?» ответом на карточку: объясняет именно её.
3. «Не понимаю, проще»: обычные слова и конкретный пример.
4. Стоп при ожидающем разрешении: старая кнопка не возобновляет задачу.
5. Стоп с очередью/фоновой работой: нет нового старта и позднего «готово».
6. Отрицательная проверка: черновик не назван готовым.
7. После паузы/новой сессии: сохраняются проблемы и открытые вопросы своего чата.

Понятность окончательно оценивает Катерина. Офлайн PASS не заменяет эту оценку. Платежи и публикации не нужны для проверки.

## Запуск и откат

Исправления находятся в исходном checkout на указанной ветке. Уже работающий Python-процесс не подхватывает их автоматически. Перезапуск здесь не выполнялся. Перед ним завершить текущую работу, убедиться в отсутствии второго polling-процесса, сохранить state; затем использовать штатный start.bat.

Для отката использовать последовательные git revert конкретных коммитов исправлений на отдельной ветке и проверку тестов, либо предыдущую проверенную версию запуска. Не применять reset/clean к текущему дереву: в нём остаются исходные журналы, локальные настройки и контентный черновик. Не восстанавливать старую копию state поверх новых сообщений; частичные результаты остаются.

Известное исходное предупреждение pytest: escape-последовательность в tests/test_guard.py. Секреты, права OAuth, внешние отправки и политика произвольного запуска не менялись.
