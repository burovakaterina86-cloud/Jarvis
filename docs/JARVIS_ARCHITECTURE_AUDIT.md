## 2. Стоит улучшить

Порядок — по пользе. Приоритеты P0–P4 — как в `docs/JARVIS_UPGRADE_PLAN.md`.

### 2.1 (P0) Guard не работает там, где сейчас идёт основная работа

- **Текущая реализация.** Guard и deny-список подключаются только флагом `--settings runtime/jarvis-settings.json`,
  который передаёт мост (ADR 0003 — сознательно, чтобы не мешать разработке). Проектного
  `.claude/settings.json` нет; `.claude/settings.local.json` только включает Playwright MCP.
- **Проблема.** В интерактивных сессиях Claude Code в этой папке (как эта) Guard не вызывается вообще:
  нет запрета на `.env`, на `git push --force`, на клик «оплатить» в браузере с её логинами. При этом
  `CLAUDE.md` и `.claude/rules/safety.md` грузятся и в эти сессии и утверждают «каждый вызов проверяет Guard» —
  это неправда в этом режиме. По журналу с 21 сентября через мост не прошёл ни один ход.
- **Предложение.** Минимальный «режим разработки» Guard: тот же `guard.py`, но с переменной
  `JARVIS_GUARD_MODE=dev` — применяются только **DENY**-правила (секреты, опасные команды, пароли/карты,
  оплата в браузере), а EXTERNAL/MONEY пропускаются к штатным запросам разрешений Claude Code (человек и так у экрана).
  Подключить в проектный `.claude/settings.json`. Плюс честная формулировка в `safety.md`.
  Требует решения владелицы: ADR 0003 это решение отменяет частично.
- **Файлы.** `.claude/hooks/guard.py`, `.claude/settings.json` (новый), `.claude/rules/safety.md`, `docs/adr/0012-*.md`, `tests/test_guard.py`.
- **Риск.** Средний: неудачное DENY-правило помешает разработке (откат — удалить `.claude/settings.json`).
- **Сложность.** Низкая (≈ 30 строк + тесты).
- **Эффект.** Защита секретов и денег во всех режимах, а не только в Telegram.

### 2.2 (P0) Тесты пишут в боевой журнал и база красная

- **Текущая реализация.** `tests/test_activation.py` и `tests/test_guard.py` запускают настоящий
  `.claude/hooks/guard.py` подпроцессом; `guard.run()` пишет `blocked` в `<ROOT>/state/events.jsonl`, где ROOT — реальный проект.
  Два теста красные ещё до аудита.
- **Проблема.** 470 из 588 строк журнала — шум тестов; по журналу нельзя понять, что делал Jarvis.
  На красной базе нельзя выполнить требование «после каждого этапа — тесты».
- **Предложение.** Подпроцессные тесты Guard — на копии хука во временной папке (как уже сделано в
  `test_approvals.py`). Найти причины двух падений (кодировка вывода `tasklist`; пропавший транскрипт в радаре) и починить.
- **Файлы.** `tests/test_activation.py`, `tests/test_guard.py`, `tests/test_bridge.py`, `tests/test_radar.py` (+ при необходимости `integrations/radar/transcribe.py`).
- **Риск.** Низкий. **Сложность.** Низкая. **Эффект.** Чистый журнал и зелёная база для всех следующих этапов.

### 2.3 (P0) Агент может переписать свой собственный слой инструкций

- **Текущая реализация.** Защищены `runtime/`, хуки, `.claude/skills|agents`. Не защищены:
  `CLAUDE.md`, `SOUL.md`, `.claude/rules/*.md`, `AGENTS.md`, `.agents/skills/**`, `.codex/**`.
- **Проблема.** Правило «новый навык — только через кнопку» обходится записью в `.agents/skills/`
  (его читает Codex) или в `.claude/rules/` (грузится в каждый ход). Недоверенный текст со страницы может
  уговорить агента «поправить правило». Guard остаётся барьером для действий, но поведение задают тексты.
- **Предложение.** Новый список `ask_write_paths` в `policy.yaml`: запись туда — EXTERNAL `self_modify`
  → кнопка с путём и диффом. Не DENY, потому что разбор поправок (`corrections-review`) по её решению
  законно пишет в `.claude/rules/` — пусть это проходит через кнопку.
- **Файлы.** `runtime/policy.yaml`, `.claude/hooks/guard.py`, `tests/test_guard.py`.
- **Риск.** Низкий; лишняя кнопка при принятии правил. **Сложность.** Низкая.
- **Эффект.** Изменение собственных правил агента всегда видно владелице.

### 2.4 (P1) Журнал не отвечает на вопросы «кто, что, почему готово»

- **Текущая реализация.** `events.jsonl`: `tool_use` пишет только имя инструмента; у субагента — `agent: "subagent"`
  без имени роли; нет идентификатора задачи, который связывает сообщение → ход → вызовы → блокировки → итог;
  `blocked` из Guard без `task`. Эпизоды (`memory/episodes`) пишет только `PreCompact`, который в коротких
  ходах `-p` не срабатывает — файл пуст.
- **Проблема.** По журналу нельзя восстановить: какие файлы изменены, сколько было попыток, что проверено,
  почему задача считается выполненной, где упала.
- **Предложение.**
  1. `task_id` на каждую `Job` (uuid), пробрасывается в `run_turn`, во все события и в окружение
     дочернего `claude` (`JARVIS_TASK_ID`) — тогда и Guard пишет его в `blocked`/`approval_*`.
  2. `tool_use` с безопасной сводкой аргументов: путь файла, домен URL, первые 200 символов команды
     через маскировку секретов (`token=…`, `Bearer …`, ключи вида `sk-…`, значения из `.env` не читаем — только шаблоны).
  3. Итоговая запись `task_done` из моста (Python, не модель): статус, длительность, число вызовов,
     список изменённых файлов (по `Write/Edit` и `git status --porcelain` до/после), попытки, вердикт ревьюера (когда появится).
  4. Эпизод в `memory/episodes/` пишет мост по концу хода — не зависит от `PreCompact` и от модели.
- **Файлы.** `runtime/events.py`, `runtime/claude_bridge.py`, `runtime/task_router.py`, `.claude/hooks/guard.py`, новый `runtime/redact.py`, тесты.
- **Риск.** Низкий-средний: утечка в лог при плохой маскировке — нужен тест на маскировку. **Сложность.** Средняя.
- **Эффект.** Пункт 9 задания закрывается целиком; основа для статусов задач и ревьюера.

### 2.5 (P1) Нет таймаута на задачу; расписание делит сессию с её чатом

- **Текущая реализация.** Предел хода — `--max-turns 60`; по времени предела нет (каждый запрос подтверждения
  может ждать до 590 с). Задачи по расписанию ставятся в очередь чата владелицы и **продолжают её сессию**
  (`sessions.get(owner_id)`), а если ход завершился с новой сессией — перезаписывают сессию её чата.
- **Проблема.** Зависший ход держит очередь чата до ручного `/stop`. Утреннее сообщение и радар
  вливаются в контекст текущего разговора: растят сессию (лимит подписки), путают контекст, а длинный разговор
  дорожает для фоновой задачи.
- **Предложение.** (а) `Job.timeout_sec` (по умолчанию, например, 45 мин; для расписания — из `schedule.json`),
  по истечении — тот же `claude_bridge.stop` и статус `timeout`. (б) `Job.context = "chat" | "isolated"`:
  расписание идёт в `isolated` — без `--resume` и без записи в `sessions.json`.
- **Файлы.** `runtime/task_router.py`, `runtime/claude_bridge.py`, `integrations/telegram/gateway.py` (`check_schedule`), `runtime/schedule.json`, тесты.
- **Риск.** Низкий. **Сложность.** Низкая.
- **Эффект.** Надёжность автономной работы; экономия лимита; первый реальный режим `isolated` из пункта 5.

### 2.6 (P1) Активация навыка не различает текст и исполняемый код; зеркала разошлись

- **Текущая реализация.** `activation.validate` проверяет имя, frontmatter, размеры, ссылки наружу.
  Навык может содержать `scripts/*.py` (как `lead-magnet-agent/scripts`, `autopilot/tools/sync.py`) —
  отдельной пометки нет. `.agents/skills/` и `.codex/agents/` — зеркала для других CLI, но расходятся
  с `.claude/` уже в 15+ навыках; у Codex-агентов нет ни ограничения инструментов, ни Guard.
- **Проблема.** Кнопка «Активировать» не говорит владелице, что вместе с навыком включается исполняемый код.
  Устаревшие зеркала — тихий второй набор поведения.
- **Предложение.** (а) `validate` выдаёт предупреждение «в черновике исполняемые файлы: …» (по расширениям
  `.py .ps1 .bat .cmd .js .sh .exe`) — показывается на кнопке, `.exe/.bat/.cmd` — запрет. (б) Скрипт
  `scripts/sync_mirrors.py --check` + тест: зеркала либо совпадают с `.claude/`, либо явно помечены
  как неподдерживаемые. Существующие навыки не меняем.
- **Файлы.** `runtime/activation.py`, `integrations/telegram/gateway.py` (текст кнопки), новый `scripts/sync_mirrors.py`, тесты.
- **Риск.** Низкий. **Сложность.** Низкая.
- **Эффект.** Шаг «security review» из пункта 7 появляется без новой бюрократии.

### 2.7 (P2) Нет независимого ревьюера в рабочем цикле

- **Текущая реализация.** Роль `reviewer` есть (только чтение, вердикт «годится / с правками / переделать»),
  `delegation.md` упоминает шаг проверки. Но ни один навык (`content-plan`, `lead-magnet-agent`, `carousel-instagram`)
  его не вызывает, а мост его не запускает. Решение «готово» принимает сам исполнитель.
- **Проблема.** Нет схемы *Worker → Independent Reviewer → возврат → DONE*. Субагент внутри той же
  сессии получает задание от исполнителя — тот сам решает, что показать проверяющему.
- **Предложение.** Проверку запускает мост (детерминированно, без «умной» логики выбора — ADR 0001 не нарушается):
  после хода, создавшего комплект/дифф, отдельный процесс `claude -p` **без `--resume`** с
  `--allowedTools Read,Grep,Glob`, системным промптом роли `reviewer` и `--json-schema` для вердикта.
  На вход только: исходный запрос, критерии готовности (из этапа 2.8), список изменённых файлов/дифф,
  результаты тестов. «Переделать» → одно сообщение исполнителю в его сессию с замечаниями → повторная
  проверка; максимум 2 круга, дальше — владелице с честным вердиктом. Включается только для существенных
  задач (есть комплект в `essa-ai/content/`, изменён код или есть файл спецификации).
  Флаги `--allowedTools`, `--json-schema`, `--no-session-persistence` в установленной версии есть
  (`claude --help`), но их работу в `-p` по подписке нужно проверить smoke-тестом **до** реализации.
- **Файлы.** новый `runtime/review.py`, `runtime/task_router.py`, `runtime/claude_bridge.py` (параметр allowed tools / schema), `runtime/prompts/review.md`, `docs/adr/0013-*.md`, тесты с фейковым claude.
- **Риск.** Средний: удваивает расход лимита на существенных задачах, ложные «переделать». **Сложность.** Средняя.
- **Эффект.** Главный рост качества: пункт 3 задания.

### 2.8 (P2) Нет этапа «спецификация до исполнения»

- **Текущая реализация.** `runtime/jarvis-turn.md`: «Если задача длинная, делай её до конца сам».
  Ни критериев готовности, ни согласования. (Для разработки есть `autopilot` с интервью, для бота — нет.)
- **Проблема.** Крупная неоднозначная задача выполняется целиком, а потом переделывается по поправкам
  (журнал `memory/corrections.md` это подтверждает).
- **Предложение.** Правило в `jarvis-turn.md` (≈ 8 строк): если задача неоднозначна **и** крупная
  (несколько артефактов, внешние действия, больше ~20 минут работы) — сначала ответ из 4 блоков
  «Сделаю / Готово, когда / Не делаю / Вопросы» и ожидание её «да». Простые задачи — без этапа.
  Согласованная спецификация сохраняется в `state/tasks/<task_id>/spec.md` — её читает ревьюер (2.7).
- **Файлы.** `runtime/jarvis-turn.md`, `CLAUDE.md` (одна строка в «Как работать»), позже `runtime/review.py`.
- **Риск.** Низкий: лишний вопрос на пограничных задачах. **Сложность.** Низкая.
- **Эффект.** Меньше переделок; у ревьюера появляются проверяемые критерии.

### 2.9 (P2) Права субагентов не различаются в Guard

- **Текущая реализация.** Ограничение — только `tools:` во frontmatter (его соблюдает Claude Code).
  Guard не знает, кто вызывает инструмент: `copywriter` с `Write` может записать в любой файл корня
  (`MEMORY.md`, `.claude/rules/`), не только в `essa-ai/content/`.
- **Предложение.** Если вход PreToolUse-хука содержит идентификатор субагента (в новых версиях Claude Code
  есть поля вида `agent_id`/`agent_type` — **в 2.1.280 не проверено**), добавить в `policy.yaml`
  раздел `agents: {copywriter: {write: ["essa-ai/content/**"]}, reels-producer: …, reviewer: {write: []}}`.
  Если поля нет — не выдумывать: оставить frontmatter и зафиксировать ограничение.
- **Файлы.** `runtime/policy.yaml`, `.claude/hooks/guard.py`, тесты.
- **Риск.** Низкий. **Сложность.** Низкая (после проверки). **Эффект.** Принцип «каждой роли — только нужные права» на уровне барьера, а не текста.

### 2.10 (P1, по решению владелицы) Shell — самый широкий инструмент

- **Текущая реализация.** `Bash`/`PowerShell` внутри корня — WRITE (без вопроса). Регулярки ловят `curl -X POST`,
  `rm`, `os.remove` в тексте команды. Guard честно пишет, что заслон неполный.
- **Проблема.** Сначала записать `x.py` с сетевым запросом или `shutil.rmtree`, потом `python x.py` —
  проходит как WRITE. `WebFetch` — READ, через адрес запроса можно вынести данные.
- **Предложение.** Список разрешённых запусков интерпретатора (`-m integrations.*`, `-m pytest`,
  `scripts/*.py`, `.claude/skills/*/scripts/*.py`); прочие `python <файл>`/`node <файл>` — EXTERNAL `run_script`
  с текстом скрипта на кнопке. Решение за владелицей: добавит кнопок.
- **Файлы.** `runtime/policy.yaml`, `.claude/hooks/guard.py`, тесты. **Риск.** Средний (трение). **Сложность.** Низкая-средняя.
- **Эффект.** Закрывает самый реальный путь обхода при prompt injection из браузера.

### 2.11 (P3) Сессия чата растёт без конца

- **Текущая реализация.** Чат — режим *fork*: каждый ход `--resume` одной сессии до переполнения,
  потом новая со сводкой последнего сообщения. Субагенты получают свежий контекст + задание (режим *brief* — это так устроен инструмент Agent).
- **Проблема.** Длинная сессия съедает 5-часовой лимит подписки (в памяти разработки уже был такой случай).
- **Предложение.** Новая сессия, если чат молчал дольше N часов (например, с утра нового дня), с
  кратким брифом из последних эпизодов (2.4). `/new` остаётся. Три режима контекста фиксируются явно:
  `chat` (fork), `isolated` (расписание, ревьюер), `brief` (новая сессия + сводка).
- **Файлы.** `runtime/task_router.py`, `runtime/sessions.py` (время последнего хода), тесты. **Риск.** Низкий: потеря «вчерашнего» контекста. **Сложность.** Низкая.
- **Эффект.** Экономия лимита и меньше шума в контексте.

### 2.12 (P3) Большие выводы инструментов

- **Текущая реализация.** `big_read` закрывает `Read`. Вывод `Bash` Claude Code обрезает сам; снимок страницы
  Playwright и `WebFetch` приходят целиком; радар уже пишет результаты в файлы (правильно).
- **Предложение.** Без нового слоя сжатия: (а) расширить `big_read` на `cat/type/Get-Content` по одному файлу
  (размер файла известен); (б) в навыке `browser-use` — правило «сначала `find`/точечный снимок, полный
  `snapshot` только при необходимости»; (в) скрипты интеграций и дальше пишут большие ответы в файлы, в контекст — сводку.
- **Файлы.** `.claude/hooks/guard.py`, `runtime/policy.yaml`, `.claude/skills/browser-use/SKILL.md` (только с её согласия — навыки сами не меняем). **Риск/сложность.** Низкие.

### 2.13 (P4) Жёсткие зависимости от Claude Code — где они мешают

| Место | Зависимость | Мешает? |
|---|---|---|
| `runtime/claude_bridge.py` | флаги CLI, формат stream-json, тексты ошибок лимита/входа | Нет — это и есть адаптер. Не хватает только общего интерфейса |
| `runtime/task_router.py` | напрямую зовёт `claude_bridge.run_turn/stop` | Немного: второй runtime потребует правки роутера |
| `.claude/hooks/guard.py` | вход PreToolUse-хука Claude Code | **Да, главное место**: у другого worker'а (Codex) защиты нет совсем. Ядро `decide()` уже чистое и переносимое |
| `runtime/jarvis-settings.json`, хуки памяти | схема настроек и событий Claude Code | Нет, пока runtime один |
| `CLAUDE.md` с `@`-импортами | синтаксис Claude Code | Нет: `SOUL/GOALS/MEMORY` — обычные файлы |
| `.claude/skills/*/SKILL.md` | формат навыков | Нет: тот же формат читают и другие агенты (`.agents/skills`) |
| Identity, memory, policy, essa-ai, расписание, Approvals, интеграции | — | Уже выше уровня модели |

Предложение на сейчас — только шов: протокол `WorkerRuntime` (`run_turn`, `stop`) и зависимость роутера
от него; `claude_bridge` — единственная реализация. Правило: **второй runtime подключается только вместе
со своим адаптером Guard**. ADR 0001 («Claude Code — единственный runtime») при этом остаётся в силе.

## 3. Пока не нужно

| Идея | Почему не сейчас |
|---|---|
| Полноценный роутер и адаптеры Codex/других моделей | Один пользователь, одна подписка; Codex без адаптера Guard — это снятие защиты. Достаточно шва из 2.13 |
| Claude Agent SDK / программное управление агентами | Новая зависимость и другая модель авторизации; текущий `claude -p` + stream-json уже даёт статусы, остановку, сессии |
| Свой планировщик subagents (параллельные воркеры, пулы, retry-политики) | Одна задача на чат — правильное ограничение для одного человека; авто-retry после вызова инструментов сознательно запрещён и должен остаться запрещённым |
| Агентные команды / Workflow-оркестрация внутри бота | Расход лимита кратно растёт; задачи владелицы укладываются в «исполнитель + ревьюер» |
| MCP-сервер памяти, векторная БД, SQLite | Память уже принадлежит Jarvis (файлы в репозитории). ADR 0006: поиск понадобится при росте, не сейчас |
| Слой автоматического сжатия tool outputs | Хуки не умеют переписывать вывод встроенных инструментов; правила + `big_read` + файлы дают 80% эффекта |
| Автогенерация навыков без человека | Противоречит ADR 0005 и пункту 7 задания |
| `--max-budget-usd` как бюджет задачи | Флаг про деньги по API; Jarvis работает по подписке — не опираться |
| Режим `fork` для веток задач (`--fork-session`) | Флаг есть, но сценария, где он нужен, сейчас нет |
| Control Room / веб-дашборд | ADR 0008; сначала журнал, из которого его можно будет построить |
