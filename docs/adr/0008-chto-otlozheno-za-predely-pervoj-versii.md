# ADR 0008 — Что сознательно отложено за пределы первой версии

- Статус: принято (2026-09-18)
- Контекст: бриф описывает систему до V2.0 — расписание, тренд-радар, Google Workspace, видео-цех, управление компьютером, Zoom, Control Room. Сделать всё сразу значит не получить ни одного работающего сценария и упереться в требование R28 («не пять агентов, не Zoom, не dashboard»). Одновременно откладывать нельзя «как получится»: если первая версия не оставит стыков, каждый следующий этап станет переписыванием.
- Решение: в первую версию входит только цепочка «Telegram → Claude Code → результат» плюс контент, браузерные поручения, память и самосоздание навыков. Отложено, каждое отдельной сборкой: тренд-радар по расписанию (V0.6 — в первой версии тренды исследуются по запросу через браузер), планировщик и состояния задач (V0.7), Google Workspace (V1.1 — нужен вход в аккаунт и выбор скоупов), видео-цех (V1.2), управление компьютером (V1.3), Zoom (V1.4 — требует решения о согласии участников, возможно платного сервиса), Control Room (V2.0). Автопубликация и оплата картой агентом не откладываются, а исключены по существу: публикует и платит владелица. Чтобы отложенное встало без переделки, в первой версии заранее фиксируются контракты, на которые оно опирается: словарь событий `state/events.jsonl` (из него вырастает Control Room), Approvals API и четыре уровня, папка `essa-ai/`, `drafts/` с активацией.
- Альтернативы: (а) строить сразу целевую архитектуру — отвергнуто: месяцы без работающего бота и нарушение R28; (б) откладывать без заложенных контрактов («потом придумаем») — отвергнуто: планировщик и пульт пришлось бы вшивать в уже живой мост; (в) выкинуть отложенное из документов совсем — отвергнуто: дорожная карта с DoD по этапам и есть то, что делает отказ обратимым.
- Последствия: первая версия реактивна — она не делает ничего, пока ей не написали; утренний радар и воскресный отчёт до V0.6/V0.7 не существуют. Часть кода написана «с запасом» под функции, которых нет (лишние поля `task`, `agent`, `progress` в событиях), и этот запас надо оправдать, иначе он станет мёртвым грузом. Каждый следующий этап обязан закрываться своим проверяемым DoD, иначе дорожная карта превратится в список пожеланий.
