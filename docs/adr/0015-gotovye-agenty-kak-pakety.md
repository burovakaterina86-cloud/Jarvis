# ADR 0015 — Готовые агенты вшиваются пакетами: навык + код + данные

- Статус: принято (2026-10-06).
- Контекст: у владелицы есть готовые рабочие агенты (первый — «Контент-план» из архива `agent-po-kontent-planu.zip`), и их будет несколько. Они написаны под Claude с коннекторами (Apify через MCP, Gmail), рассчитаны на сеанс в 1,5–2 часа и на 70 КБ инструкции целиком. У JARVIS другое устройство: мост без MCP, лимит подписки, Guard, правило «файл больше ~30 КБ целиком не читаем».
- Решение:
  1. Каждый агент раскладывается на **навык** (тонкий вход + этапы в `references/`), **код** (`integrations/<имя>/`, Python без токенов Claude), **данные** (`essa-ai/<имя>/`, исходники агента в `upstream/` только для `Grep`) — по `docs/AGENT_PACKS.md`.
  2. Сервисы вызываются по REST из Python (ключ — имя в `.env`), потолок трат в паспорте, расчёт до вызова; коннекторы, почта и публикация убираются.
  3. Этапы сохраняют состояние файлами в папке недели — лимит подписки не сбрасывает работу.
  4. Расписание — обработчик Python, Claude подключается только на думающие этапы.
- Альтернативы: (а) копировать папку агента целиком и запускать как есть — отвергнуто: нет MCP и почты, 70 КБ инструкции не читаются целиком, сеанс на 2 часа упирается в лимит; (б) подключить Apify как MCP-сервер в мост — отвергнуто: расширяет доверенную поверхность, а REST-клиент с потолком трат уже есть (радар); (в) переписать агента с нуля — отвергнуто: метод проверен автором, переписываем только обвязку.
- Последствия: каждый новый агент начинается с таблицы «что не стыкуется» и вопросов владелице; общие куски (клиент Apify, потолок трат, история) со временем выносятся в общий модуль, когда появится второй пользователь.
