# ADR 0003 — Настройки агента живут в `runtime/jarvis-settings.json`, а не в `.claude/settings.json`

- Статус: принято (2026-09-18)
- Контекст: D01 (обнаружено при сборке): проектный `.claude/settings.json` применяется ко всем сессиям Claude Code в этой папке — включая сессии, в которых JARVIS разрабатывают. Строгие deny-правила и Guard, нужные боевому агенту (запрет чтения `.env`, записи в `runtime/`, `.claude/hooks/`, подтверждение на удаление), заблокировали бы саму сборку: разработчик не смог бы править собственный мост. Слить оба режима в один файл нельзя — послабление для разработки стало бы послаблением для агента.
- Решение: разрешения и хуки боевого агента вынесены в отдельный файл `runtime/jarvis-settings.json`, который мост передаёт флагом `--settings` при каждом запуске `claude -p`. Проектный `.claude/settings.json` остаётся обычным файлом разработки. Записывать в оба файла агенту запрещено — их меняет только владелица руками.
- Альтернативы: (а) держать всё в `.claude/settings.json` — отвергнуто, ломает разработку и провоцирует ослабление правил «на время»; (б) переключать профили симлинком/переименованием — отвергнуто: состояние на диске, легко забыть, на Windows хрупко; (в) разрешения флагами командной строки — отвергнуто: длинные списки, не переживают Windows-лимит строки, не версионируются человекочитаемо.
- Последствия: два файла настроек вместо одного, и их легко спутать — тест сборки специально проверяет, что запись в `runtime/jarvis-settings.json` из агента отклоняется. Разработчик, который правит `.claude/settings.json`, не меняет поведение бота: настройки бота надо править в `runtime/`, перечитываются они только при следующем запуске хода. Локальные проверки «как у агента» требуют вручную запускать `claude` с тем же `--settings`, иначе они ничего не доказывают.
