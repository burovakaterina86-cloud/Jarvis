# ADR 0011 — Состав базовых ролей проверяется по рабочему дереву, а не по истории

- Статус: принято (2026-09-20)
- Контекст: D03, обнаружено прогоном 2026-09-20. Включение помощника кнопкой переносит его файл из `drafts/agents/` в `.claude/agents/` (ADR 0005), и после коммита этот перенос попадает в историю. Тесты состава поставки, читавшие `git ls-tree HEAD drafts/agents`, стали красными после коммита активации: у владелицы роли уже включены, а тест ищет их там, откуда они ушли.
- Решение: «состав поставки базовых ролей» нельзя проверять по содержимому `drafts/agents` в `HEAD`. Базовая роль существует ровно в одном из двух мест — черновиком или уже включённой; проверка требований истории 55 (минимальные инструменты, голос, только чтение у `researcher` и `reviewer`) идёт по тому файлу, который лежит на диске сейчас. Само требование не меняется — меняется способ его проверки. Служит R33, R34.
- Альтернативы: (а) оставить проверку по `HEAD` — отвергнуто: тест краснеет не от поломки, а от штатной активации, то есть наказывает за нормальную работу; (б) запретить активации трогать `drafts/` — отвергнуто: карантин и перенос как раз и есть механизм защиты из ADR 0005.
- Последствия: тест перестаёт зависеть от истории git и начинает зависеть от состояния диска — значит, он проверяет то, что у владелицы реально работает, но уже не ловит удаление роли из поставки как таковое. Каждая проверка «что поставлено» теперь обязана искать файл в обоих местах, иначе снова разойдётся с реальностью после первой же кнопки.
