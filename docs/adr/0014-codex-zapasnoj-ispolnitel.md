# ADR 0014 — Codex — запасной исполнитель, только с Guard и по её кнопке

- Статус: принято (2026-10-05). Уточняет ADR 0001 («Claude Code — единственный runtime»): Claude остаётся основным, Codex подключается на время, когда у Claude кончился лимит подписки.
- Контекст: владелица пользуется и Claude Code, и Codex (подписка ChatGPT). Когда у Claude кончается 5-часовой лимит, работа встаёт до сброса. Исследование `docs/CODEX_RESEARCH.md` (живые прогоны на её Codex 0.157.0) показало: у Codex есть хук `PreToolUse`, но он слушает только JSON-запрет (код 2 игнорирует), пропускает вызов, если хук упал, и не работает в недоверенной папке.
- Решение:
  1. **Guard для Codex** — тот же `guard.py` с `--runtime codex` из `.codex/hooks.json`: вход Codex переводится в события Guard (`Bash` — как есть; `apply_patch` — по каждому файлу патча), решает тот же `decide()`, ответ всегда JSON, любая ошибка — запрет. Есть `JARVIS_TASK_ID` (ставит бот) — полный режим с кнопками; нет — режим разработки. `.codex/hooks.json` агенту — DENY.
  2. **Доверие к хукам** владелица подтверждает сама один раз (`/hooks` в Codex), флаг обхода доверия бот не использует. Перед каждым запуском Codex мост проверяет хук канарейкой без Codex (`preflight_hook`), а раз в 6 часов — короткий ход Codex с командой-канарейкой (`ensure_ready`): Guard не ответил — Codex не запускается, владелице уходит инструкция.
  3. **Мост** `runtime/codex_bridge.py` — тот же контракт, что `claude_bridge.run_turn`: `codex exec --json` (`exec resume <thread>` для продолжения), «мозг» Jarvis через `developer_instructions`, её `~/.codex/config.toml` грузится (в нём доверие к папке; без него Codex включает read-only и не запускает хуки), её плагины отключены (`--disable plugins`), `node codex.js` вместо `codex.cmd` (cmd.exe портит аргументы). Проверяющий в режиме Codex — тоже Codex (`read-only`, `--output-schema`, `--ephemeral`).
  4. **Переключение по её кнопке**: лимит Claude → сообщение «⏳ Лимит Claude закончился, обновится в ЧЧ:ММ; задача … не доделана: …» и кнопки «Продолжить в Codex» / «Подождать до ЧЧ:ММ». Codex получает сводку (запрос, план, уже изменённые файлы); карточка и ответы помечены «🟢 Codex». В момент сброса лимита бот сам возвращается к Claude со сводкой сделанного в Codex и говорит об этом. `/codex`, `/claude` — вручную; `/status` — кто работает и лимиты обеих подписок. Состояние — `state/runtime.json`, `limits.json`, `offers/`, `deferred.json`.
- Альтернативы: (а) автоматическое переключение — отвергнуто владелицей: решение за ней и должно быть понятным; (б) `--dangerously-bypass-hook-trust` у бота — отвергнуто: Codex перестал бы сверять файл хуков с её одобрением; (в) песочница Codex без Guard — отвергнуто: нет секретов, кнопок, денег и прав ролей; (г) `--ignore-user-config` — отвергнуто: папка становится недоверенной, хуки не запускаются.
- Последствия: сессии Claude и Codex разные — контекст между ними передаётся сводкой, не историей. Расход переходит на подписку ChatGPT. Как Codex сообщает об исчерпании своего лимита — не проверено (определяем по тексту ошибки, сырое сообщение пишется в журнал). Сообщение её MCP-сервера в stderr Codex — шум. Также включён `concurrent_updates(True)` у бота: без него кнопки и команды во время хода ждали бы его конца.
