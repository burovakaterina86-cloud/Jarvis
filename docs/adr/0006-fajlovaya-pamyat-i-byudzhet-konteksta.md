# ADR 0006 — Память — файлы и бюджет контекста ≤ 12 KB каждым ходом, без базы данных

- Статус: принято (2026-09-18)
- Контекст: главный расход личного агента — контекст, а не диск. Если каждым ходом грузить всё, что агент когда-либо узнал, ходов на подписке станет мало, а качество упадёт. R28 прямо запрещает сложную БД в первой версии. При этом «запомни» должно переживать сессии, и владелица должна видеть, что именно записано.
- Решение: память — обычные Markdown-файлы, подключённые импортом `@` в `CLAUDE.md`. Каждым ходом грузится только постоянное ядро: `CLAUDE.md` (≤5 KB), `SOUL.md` (≤2 KB), `GOALS.md` (≤2 KB), `MEMORY.md` (≤5 KB) — суммарно ≤ 12 KB, размеры проверяет скрипт и хук `SessionStart`. В `CLAUDE.md` лежит только карта «что где лежит»; навыки, `essa-ai/`, `memory/`, `docs/REFERENCE.md` читаются по необходимости. Уровни памяти выбирает сам агент по `.claude/rules/memory.md`: сессия / `MEMORY.md` (20–50 важнейших фактов) / `memory/{decisions,projects,people}` / `essa-ai/knowledge`. Каждая запись подтверждается строкой «🧠 запомнил: … (файл)» через хук `PostToolUse`. Переполнение `MEMORY.md` — команда сжать и вынести детали в `memory/`. Историю сжимает сам Claude Code (auto-compact), хук `PreCompact` пишет итог в `memory/episodes/YYYY-MM.jsonl` — одна строка на завершённую задачу; хук `Stop` спрашивает про урок и кандидата в навыки.
- Альтернативы: (а) SQLite/векторная база с поиском по памяти — отвергнуто (R28): схема, миграции и эмбеддинги ради объёма, которого у одного человека пока нет; файл владелица может открыть и исправить руками, строку в БД — нет; (б) грузить всю память каждым ходом — отвергнуто: съедает подписку и топит важное в шуме; (в) память только в истории сессии — отвергнуто: не переживает `/new`, компакт и перезапуск.
- Последствия: «вспомнить» — значит открыть нужный файл, поэтому качество памяти держится на дисциплине правил и на честных описаниях: плохо названный файл в `memory/` фактически потерян. Поиска по всей памяти нет — по мере роста придётся вводить индекс или возвращаться к БД (контракт `events.jsonl` и `episodes` заложен так, чтобы это не было переписыванием). Потолок 12 KB жёсткий: каждый новый постоянный факт вытесняет старый, и решение «что важнее» принимается регулярно. Хуки памяти — часть цепочки подтверждений, их поломка видна сразу по исчезнувшей строке «🧠 запомнил».
