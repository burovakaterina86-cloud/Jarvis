# ADR 0001 — Claude Code — единственный агентный runtime, Python — тонкий мост

- Статус: принято (2026-09-18)
- Контекст: агент нужен один человеку, на домашнем Windows, с уже оплаченной подпиской Claude. Готовые «Джарвисы» (OpenClaw и подобные) тащат свой оркестратор, свою память и свой цикл планирования — это второй мозг поверх Claude Code: лишний контекст, лишние ключи, расходящееся поведение. Соблазн написать «умный» Python-роутер (выбор навыка, разбор намерения, план шагов) существует ровно до первого расхождения между тем, что решил Python, и тем, что решил бы Claude.
- Решение: думает, планирует, выбирает навыки и субагентов только Claude Code. Python отвечает за транспорт и ничего больше: Telegram-апдейты, allow-list, распознавание голоса, очередь ходов, запуск `claude -p --output-format stream-json --resume`, разбор потока событий, отправка ответа. `runtime/task_router.py` ведёт очередь и передаёт `session_id` — он не выбирает навык. Карта «что где лежит» живёт в `CLAUDE.md`, а не в коде моста.
- Альтернативы: (а) OpenClaw / готовый фреймворк — отвергнут: чужая обвязка, широкий доступ агента к системе, жжёт контекст; (б) свой LLM-оркестратор на Python поверх API — отвергнут: требует API-ключ (платим дважды при наличии подписки), дублирует то, что Claude Code уже умеет, и ломает подтверждения через хуки; (в) `claude --bare` — отвергнут: не видит подписку, хуки и навыки.
- Последствия: возможности JARVIS ограничены возможностями CLI Claude Code — что нельзя выразить флагом, хуком, навыком или MCP, того у нас нет. Обновление CLI может сломать разбор `stream-json`, поэтому мост тестируется через подменённый исполняемый файл (фейковый `claude`). Мы сознательно отказываемся от «умного» Python: любую логику выбора добавляем в `CLAUDE.md` и описания навыков, а не в `task_router.py`. Кросс-платформенность и работа без подписки не рассматриваются.
