# ADR 0012 — Guard и в сессиях разработки: только жёсткие запреты

- Статус: принято (2026-10-05), частично отменяет ADR 0003.
- Контекст: ADR 0003 вынес Guard и deny-список в `runtime/jarvis-settings.json`, который передаёт только мост, — чтобы строгие правила бота не мешали разработке. Аудит 2026-10-05 показал цену: с 21 сентября вся работа шла в интерактивных сессиях Claude Code в этой папке, а там Guard не вызывался вовсе — ни запрета на секреты, ни на опасные команды, ни на оплату в браузере с её логинами. При этом `CLAUDE.md` и `.claude/rules/safety.md` грузятся и туда и утверждали обратное.
- Решение: проектный `.claude/settings.json` подключает тот же `guard.py` с аргументом `--mode dev`. В этом режиме действуют только отказы видов из `policy.yaml: dev_mode.deny_kinds` — `secret`, `dangerous`, `secret_field`, `purchase`, `malformed`. Защищённые пути и правка собственных правил сняты (разработчик правит код JARVIS); правила «на любой инструмент» смотрят только на исполняемое (shell, MCP), а не на текст документов; EXTERNAL/MONEY не идут в Approvals API — их решают штатные разрешения Claude Code, человек у экрана. Отказ пишется в `state/events.jsonl` строкой `blocked` с `"mode": "dev"`. Режим передаётся аргументом, а не переменной окружения: бот, запущенный из сессии разработки, не должен унаследовать облегчённый режим; неизвестный режим или лишний аргумент — отказ.
- Альтернативы: (а) оставить как было — отвергнуто: секреты и деньги без защиты в основном режиме работы; (б) полный Guard в разработке — отвергнуто по ADR 0003: без кнопок Telegram и с защищёнными путями разработка встаёт; (в) режим через `env` в `.claude/settings.json` — отвергнуто: переменная `JARVIS_*` проходит в окружение бота через `build_env`.
- Последствия: в сессиях разработки нельзя читать `.env*`, искать по слову `credentials`, запускать опасные команды и нажимать «оплатить» — даже если очень надо; такие вещи владелица делает руками. Hook-ошибка (нет `.venv`) блокирует все инструменты сессии — fail-closed, как у бота. `scripts/check_hooks.py` проверяет и dev-хук.
