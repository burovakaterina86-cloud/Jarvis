# ADR 0004 — Работа по подписке владелицы: окружение дочернего процесса чистится от всех `CLAUDE*`/`ANTHROPIC*`

- Статус: принято (2026-09-18)
- Контекст: R04 требует, чтобы агент думал по существующей подписке, без API-ключа. D02 (живой прогон бота 2026-09-18): сессия Claude Code передаёт дочерним процессам служебное окружение (`ANTHROPIC_BASE_URL`, `CLAUDE_CODE_*`), и запущенный из-под неё `claude -p` отвечает `auth_required` вместо того, чтобы работать по подписке. Удалять точечно один `ANTHROPIC_API_KEY` оказалось недостаточно: ломает не тот ключ, который ожидали, а унаследованный базовый URL.
- Решение: мост строит окружение дочернего процесса сам (`build_env`) и вычищает из него все переменные с префиксами `CLAUDE` и `ANTHROPIC` — целыми классами, а не списком известных имён. Единственное исключение — `CLAUDE_CODE_GIT_BASH_PATH`, нужный на Windows. API-ключ в проект не заводится вовсе: аутентификация — вход владелицы в Claude на её компьютере. Ошибки `authentication_failed` и `rate_limit` мост переводит на человеческий язык («нужно заново войти в Claude на компьютере», «лимит подписки, продолжу в HH:MM»). Условия Anthropic: личное использование немодифицированного `claude` своим логином, рассчитанное на обычную индивидуальную нагрузку — поэтому в мосте есть настраиваемый дневной бюджет запусков и нет круглосуточного фонового «жжения»; продажа агентов клиентам снята из объёма.
- Альтернативы: (а) API-ключ вместо подписки — отвергнут: отдельные деньги поверх оплаченной подписки, отдельный секрет, который агент мог бы утечь; (б) удалять перечисленные переменные поимённо — отвергнуто D02: список неполон и меняется с версиями CLI; (в) наследовать окружение как есть — не работает, `auth_required`.
- Последствия: JARVIS живёт и умирает вместе с логином владелицы — истёк вход, и бот молчит, пока она не залогинится руками; автоматического обхода нет и не будет. Мощность ограничена лимитами подписки, а не деньгами: тяжёлые сценарии (видео-цех, круглосуточный радар) упираются в потолок, а не в счёт. Полная чистка префиксов может однажды выкинуть переменную, которая новому CLI нужна, — это первое место, куда смотреть при странном поведении дочернего процесса. Запуск бота из-под сессии Claude Code остаётся особым случаем и требует отдельной проверки.
