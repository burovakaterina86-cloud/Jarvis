# Собеседник JARVIS — первый этап, 7 октября 2026

Каждое обычное сообщение сначала получает отдельный собеседник на Claude Haiku. Его очередь независима от рабочих задач. Длинные и многострочные вопросы проходят тот же вход. Команды, кнопки разрешений и объяснение действующего разрешения обрабатываются непосредственно ботом.

Собеседник может ответить, уточнить задачу или передать одно поручение одной специализации: исследования, тексты, карусели, монтаж, лид-магнит, визуал, радар, техническая задача. Он не читает файлы и не запускает команды. Его CLI запускается в safe-mode, без MCP, плагинов, автоматического контекста проекта и файловых инструментов; служебный StructuredOutput формирует ответ по схеме.

Новая задача получает свою сессию. Правка завершённой задачи возвращается её агенту и аккаунту; идентификатор, чат и роль проверяются. Другую специализацию нужно оформить отдельной задачей. Рабочие задачи пока выполняются последовательно, разговор — параллельно с ними. Одновременная запись несколькими специалистами требует следующего этапа с правами и разделением каталогов.

Подключённый второй профиль Claude используется для разговора по умолчанию. Если его нет, используется первый. `JARVIS_CONVERSATION_RUNTIME=claude` или `claude2` задаёт аккаунт явно. `/claude`, `/codex`, `/claude2` выбирают рабочего исполнителя; аккаунт разговора от этого не меняется. Haiku разговора задан явно, обычные рабочие модели сохраняют прежнюю настройку.

История: `state/conversation/<chat>.jsonl`. Вход записывается до модели, даже если она позже не ответит. Модель видит последние восемь пар разговора, исходный журнал не обрезается. `/new` добавляет границу нового разговора, не удаляя историю.

Карточки: `state/tasks/<task_id>.json`; старые версии — `state/tasks/versions/`; краткие итоги для собеседника — `state/tasks/summaries/`. Исходное поручение сохраняется целиком. Последние четыре карточки своего чата дают собеседнику фактические результаты, файлы и статус приёмки. Полная рабочая история не смешивается с разговором. Автоматического повторного исполнения после перезапуска нет.

При ошибке схемы, лимите или недоступности модели сообщение сохраняется, но задача не создаётся. Бот сообщает о сбое; `/status` и `/stop` доступны без модели. Разговор не тратит внутренний дневной бюджет рабочих задач, но использует лимит подписки Claude. «Всегда доступен» означает отсутствие ожидания рабочей очереди; доступность внешней модели и сети гарантировать нельзя.

Проверка без Telegram: `.venv\Scripts\python.exe -m scripts.probe_conversation --account claude2`. Первый аккаунт вернул rate_limited, второй Haiku дал корректный ответ по схеме за 5.28 и 5.50 секунды в двух пробах; единственный служебный вызов — StructuredOutput. Это измерения двух запросов, не гарантия срока каждого ответа.

Полноценные отдельные права, инструменты и файловые каталоги специализаций — следующий этап. Сейчас выполнены разделение разговора и исполнения, маршрутизация ролей, независимость сессий, сохранение исходников и проверка результата. Запрет вызова других агентов действует в Claude и сохраняется при исправлениях; для Codex ограничения ролей пока задаются текстом, отдельный контроль требует следующего этапа.

Живой Telegram-бот этой разработкой не перезапускался. Новая схема заработает после контролируемого перезапуска.
