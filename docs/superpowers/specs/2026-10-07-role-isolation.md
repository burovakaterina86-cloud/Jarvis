# Отдельные конфигурации ролей

Катерина поручила разделить память, поведение, навыки, инструменты и результаты каждой роли. Существующие материалы не перемещаем и не удаляем; отдельные сессии задач сохраняются, переключение Claude/Codex не ослабляет ограничения.

Конфигурация каждой роли — runtime/roles/<role>/profile.json и behavior.md. Рабочие роли: research, text, carousel, montage, lead_magnet, visual, radar, technical, builder. Reviewer — отдельный профиль независимой проверки, не исполнитель. Собеседник сохраняет свой прежний профиль без инструментов.

На запуске загружается только инструкция выбранной роли, разрешённый список навыков, её собственная память и конкретное поручение. Общий CLAUDE/SOUL/MEMORY и полный каталог навыков не загружаются. Claude использует специальный системный промпт и отключение CLAUDE.md через официальный env, хуки сохраняются; Codex получает тот же выбранный промпт, проектные документы отключены как прежде.

Память: state/agent-memory/<chat>/<role>/episodes.jsonl — эпизоды с проверенным статусом, результатом и приёмкой; модель получает только принятые итоги. Агент не читает и не меняет этот журнал напрямую. Результаты: outbox/agents/<chat>/<role>/<task_id>/. Входные материалы доступны на чтение в inbox и essa-ai; чужие результаты передаются как данные в тексте конкретного поручения, не через общий каталог. Автоматическая передача файлов между ролями не входит в это изменение.

Guard получает роль через окружение моста, не из ответа модели. Неизвестная роль, запрещённый инструмент, чужая память/результат, другой навык, путь вне разрешённой области, симлинк наружу — отказ. Все прежние запреты секретов, внешних действий и платежей остаются. Свободные shell-команды исключены; разрешён только доверенный integrations.role_tools с запросом из собственной папки результатов. Он повторно проверяет роль, пути и операцию. Код из папки результатов не запускается. Это границы доступа инструментов, не отдельная виртуальная машина.

Существующие сессии задач, созданные до разделения, нельзя продолжать с прежним широким контекстом: первый запуск нового профиля получает сохранённое поручение и итог предыдущего исполнения, затем отдельный ключ сессии версии профиля. Старые сессии не удаляются.

Ревью использует отдельный read-only профиль, входные бизнес-материалы и файлы проверяемой задачи. Исправляющие ходы используют исходный профиль исполнителя. Выдача файлов и проверка публичных текстов поддерживают новую папку результатов; готовность не подтверждается без необходимых проверок. Для Codex недоступные визуальные/бинарные и обрезанные данные означают check_unavailable. Свободный запуск монтажа, генерации и черновиков не разрешается; пока доверенный помощник даёт read/list/search/carousel. Старые задачи расписания без роли сохраняются; их миграция отдельная.

Приёмка: конфигурации валидны и ссылаются на существующие навыки; промпт не содержит чужих навыков/памяти; Guard отвергает обходы; роль проходит Claude/Codex, review и fix; сохранены входные данные и прежние сессии; выдаются артефакты собственной задачи; полный pytest, контекст, зеркала и хуки зелёные. Бот не перезапускается в ходе разработки.
