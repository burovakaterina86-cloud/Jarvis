# Отдельные роли JARVIS

Каждое поручение собеседника получает собственный профиль. Файлы конфигурации — `runtime/roles/<роль>/profile.json` (навыки, инструменты, память, результаты) и `behavior.md` (поведение). Ограничения исполняет Guard; они действуют для Claude, второго Claude и Codex.

| Роль | Работа | Разрешённые навыки |
|---|---|---|
| research | Исследования и источники | competitor-research, transcript, instagram-superpower |
| text | Тексты | textwriter, humaniser, copywriting, threads-content, repurpose-content |
| carousel | Карусели из утверждённого материала | carousel-instagram |
| montage | Монтажный план | reel-montage, transcript |
| lead_magnet | Лид-магниты | lead-magnet-agent, textwriter, humaniser, site-builder |
| visual | Визуальные концепции и задания | visual |
| radar | Темы и сигналы со ссылками | reel-radar, topic-monitor, trend-radar |
| technical | Технический анализ и черновики | create-skill, create-agent, site-builder |
| builder | Проектирование пайплайнов | create-skill, create-agent |
| reviewer | Независимая проверка | Без производственных навыков, только чтение |

Собеседник сохраняет отдельную очередь, лёгкую модель Haiku и свой журнал разговора; файловых инструментов у него нет. Он не может отправить файл через служебную строку вложения. Исполнители используют отдельные сессии задач. Работы с файлами по-прежнему идут последовательно; разговор от их очереди не зависит.

Память каждой роли: `state/agent-memory/<чат>/<роль>/episodes.jsonl`. Журнал пишет мост. В следующий контекст попадают только итоги с успешным статусом и принятой независимой проверкой. Сам журнал недоступен агенту для чтения и изменения, чтобы отклонённый итог не вернулся как факт. Общая память и инструкции общего агента в профиль не подмешиваются.

Результаты каждой задачи: `outbox/agents/<чат>/<роль>/<task_id>/`. Агент может писать только туда; технические черновики также остаются здесь. Входные бизнес-материалы `essa-ai` и загруженные файлы `inbox` доступны на чтение с прежней защитой секретов. Результат другой роли можно передать в тексте нового поручения. Прямой доступ к чужим каталогам закрыт; автоматический конвейер передачи артефактов в этом изменении не добавлен.

Для команд разрешён только типизированный помощник: абсолютный интерпретатор проекта, модуль `integrations.role_tools`, файл запроса JSON из своей задачи и рабочий каталог в корне проекта. Он поддерживает ограниченные `read`, `list`, `search` и сборку `carousel` для роли каруселей. Командные цепочки, подстановки, чужой интерпретатор, запуск написанного агентом кода и другой рабочий каталог запрещены. Ресурсы сборки и симлинки проверяются отдельно.

Монтаж видео, платная генерация изображений, публикация, новые MCP-инструменты и запуск технических черновиков через этот помощник пока не подключены. У этих ролей есть отдельный контекст и права на подготовку результата; это не означает, что все операции из их навыков уже доступны. Их доверенные операции следует подключать отдельными проверяемыми изменениями.

Ревью получает отдельный профиль без права записи. Исправление возвращается исходному исполнителю с его прежними ограничениями. Codex reviewer получает текстовое содержимое файлов от моста. Бинарный, отсутствующий, обрезанный либо слишком большой результат помечается `check_unavailable`, даже при ответе `pass`; полноценной визуальной проверки это не заменяет. Публичные тексты в каталогах text и lead_magnet сохраняют проверку textwriter → humaniser по журналу выполненных операций.

Продолжение, переключение аккаунта и кнопка ожидания лимита сохраняют роль и идентификатор задачи. Ключ новой сессии содержит `roles-v1`; старая широкая сессия не возобновляется. Старые сессии и материалы не удаляются; предыдущий итог своей задачи передаётся как данные с явной оговоркой о проверке.

Старые задачи расписания без назначенной роли сохраняют прежний запуск. Перенос расписания на явные роли — отдельная миграция. Эти ограничения действуют на инструменты агента; отдельные виртуальные машины или ОС-пользователи не создавались.

Изменение начнёт действовать после перезапуска бота. В ходе разработки бот не перезапускался. Для отката — revert коммита кода; новые каталоги памяти и результатов сохранять, `state` не удалять.

Проверки: `tests/test_role_profiles.py`, `tests/test_conversation.py`, `tests/test_worker.py`, полный pytest, проверки контекста, зеркал и хуков. Реальный ход профиля через внешний Claude не выполнен: автоматическая проверка разрешений потребовала отдельного согласия на передачу содержимого локального навыка. Локальные тесты не подтверждают живой запуск всех CLI.
