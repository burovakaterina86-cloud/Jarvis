# Спецификация: ESSA-JARVIS

> Глубина: обычная. Объём прогона (ответ «Да, так»): **архитектура всей системы → «ок» пользователя → первая рабочая версия**. Всё, что после неё, спроектировано здесь, но строится отдельными сборками.
> 2026-09-17: по решению владелицы убраны Умида и всё про клиентов — это личный агент владелицы, один бизнес-контекст ESSA.AI.
> Исследование референсов: `scratchpad/research/01–03` (итоги перенесены в §«Что берём у референсов»).

## Задача

Владелица ESSA.AI ведёт соцсети своего проекта и тратит часы на то, чтобы перекладывать материалы между ChatGPT, Claude, браузером и файлами. Готовые «Джарвисы» (OpenClaw и подобные) тащат тяжёлую обвязку, жгут контекст и дают агенту слишком широкий доступ. Ей нужен свой агент, которому можно написать или наговорить задачу с телефона, и он доведёт её до результата сам — контент, исследование, покупки в интернете, поручения — а дальше будет расти: сам заводить себе навыки и помощников, работать по расписанию, с почтой, видео, встречами.

## Решение

В Telegram появляется личный бот JARVIS, который слушается только владелицу. Ему пишут текстом или голосом:

- «Сделай контент для ESSA на завтра» — он читает цели и голос бренда, смотрит тренды и конкурентов в браузере, выбирает тему и присылает пост, Reels-сценарий и Stories. Ничего не публикует.
- «Положи в корзину Самоката молоко и хлеб» / «Подбери билеты в Москву на пятницу» — открывает сайт в своём браузере (где владелица один раз залогинилась сама), собирает корзину или три варианта билетов и присылает скриншот. Оплату, бронирование, отправку сообщений людям он не делает без нажатия «Подтвердить» в Telegram — и никогда не вводит пароли и карты.
- «Запомни: в ESSA не используем эмодзи в постах» — сохраняет в память и сообщает, что сохранил.
- Когда задача повторяется, он предлагает: «Я написал новый навык instagram-competitor-audit, тест пройден. Активировать?» — и навык появляется только после «Да». Так же — новые помощники-субагенты.
- Пока он работает, в Telegram обновляется одно сообщение-статус: что делает, какой инструмент, сколько идёт.

Под капотом Python только передаёт сообщения; думает, планирует и действует сам Claude Code по подписке владелицы.

## Архитектура одним взглядом

```text
Telegram (текст / голос / фото / файлы)
   │
   ▼
Gateway — Python, python-telegram-bot            ← только владелица (allow-list)
   │  голос → faster-whisper (локально)
   │  очередь: одна задача за раз на сессию
   ▼
Bridge — запуск `claude -p` (stream-json, --resume) ← подписка, без API-ключа
   │  поток событий → статус в Telegram + state/events.jsonl
   ▼
Claude Code (cwd = корень JARVIS)
   ├── всегда в контексте: CLAUDE.md → @SOUL.md @GOALS.md @MEMORY.md  (≤ 12 KB суммарно)
   ├── по необходимости: .claude/skills/*, essa-ai/*, memory/*, docs/REFERENCE.md
   ├── субагенты .claude/agents/* — создаются под задачу
   ├── MCP: Playwright (свой профиль браузера)   [позже: TrendRadar, desktop, Google]
   └── Guard-хук PreToolUse (на ВСЕ инструменты) ──► Approvals API моста ──► кнопки в Telegram
```

## Потоки данных

1. **Сообщение.** Telegram → `integrations/telegram` (allow-list; голос → текст; файл → `inbox/`) → `task_router` (очередь) → `claude_bridge` (`claude -p … --resume`) → поток событий → статус в Telegram + `events.jsonl` → итоговый текст/файлы → Telegram; `session_id` → `sessions.json`.
2. **Подтверждение.** Claude вызывает инструмент → Guard (PreToolUse) классифицирует по `policy.yaml` → READ/WRITE: пропуск; запрещённое: exit 2 + событие `blocked`; EXTERNAL/MONEY: `POST 127.0.0.1/approve` → `approvals` → кнопки в Telegram → решение → Guard пропускает или отклоняет → `approvals.jsonl`.
3. **Память.** Агент решает уровень по `rules/memory.md` → пишет файл → PostToolUse `memory_notice` → строка «🧠 запомнил» в ответ; Stop `capture_learning` → урок/кандидат навыка; PreCompact → итог в `episodes`.
4. **Файлы и фото.** Telegram → `inbox/YYYY-MM-DD/<очищенное имя>` → путь в промпт → агент читает; по указанию — перенос в `essa-ai/knowledge/`.
5. **Браузерное поручение.** Агент → Playwright MCP (профиль `state/browser-profile`) → страницы — недоверенные данные → черновик результата/корзина → скриншот в Telegram → действие отправки/оплаты — через поток 2.
6. **Новый навык/агент.** Агент → `drafts/…` + `TEST.md` → мост замечает черновик → кнопки → `activation.activate` переносит в `.claude/skills|agents` → живая перезагрузка.

### Безопасность

| # | Метка | История | Приёмка |
|---|-------|---------|---------|
| 44 | R13 | Агент никогда не запускается с полным обходом прав | мост вызывает `--permission-mode dontAsk` + разрешения из `.claude/settings.json`; флага `--dangerously-skip-permissions` нет нигде; тест проверяет строку запуска |
| 45 | R14 | Действия разделены на 4 уровня | READ — сразу; WRITE внутри корня JARVIS — сразу; EXTERNAL (отправить, опубликовать, ответить человеку, зарегистрировать) — кнопка «Подтвердить»; IRREVERSIBLE/MONEY (оплата, бронь, покупка, удаление) — всегда кнопка «Подтвердить» с явным текстом суммы/объекта, без возможности отключить |
| 45a | R14.3 | EXTERNAL-действия настраиваются политикой | `policy.yaml` для каждого вида EXTERNAL: `ask` (по умолчанию) или `auto` (например, сообщение самой владелице); MONEY/IRREVERSIBLE — только `ask`, настройка игнорируется |
| 46 | R14.1 | Подтверждение нельзя обойти промптом | Guard-хук (PreToolUse, matcher `*`, включая `mcp__*`) классифицирует вызов, для EXTERNAL/MONEY делает HTTP-запрос к Approvals API моста и ждёт ответа; нет ответа за 10 мин → отказ; ошибка хука → отказ (fail-closed, exit 2) |
| 47 | R14.2 | Кнопка подтверждения говорит, что именно произойдёт | «Отправить ответ @user: "…"? [Подтвердить] [Отклонить]»; решение пишется в `state/approvals.jsonl` |
| 48 | R15 | Секреты недоступны агенту | deny-правила и Guard-хук: `.env*`, `**/credentials*`, `~/.claude/.credentials.json`, `~/.ssh`, `state/browser-profile/` (прямое чтение), `state/secrets/`; Bash/PowerShell-команды, упоминающие эти пути, — отказ |
| 49 | R15.1 | Опасные команды блокируются | любое удаление файлов (`rm`, `del`, `Remove-Item`) — уровень IRREVERSIBLE, через «Подтвердить»; `format`, `git push --force`, `reg`, `schtasks`, `Set-ExecutionPolicy`, скачивание и запуск exe — отказ |
| 50 | R15.2 | Агент не может ослабить собственную защиту | запрет на запись в `.claude/settings*.json`, `.claude/hooks/`, `runtime/`, `integrations/`, `.env*`; изменения — только владелица руками |

## Решения по реализации

1. **Python 3.12, python-telegram-bot (async).** Почему: зрелая, polling без публичного адреса — компьютер дома не нужно открывать в интернет.
2. **Вызов Claude: `claude -p --output-format stream-json --verbose --resume <sid> --permission-mode dontAsk --append-system-prompt-file runtime/jarvis-turn.md --max-turns 60`, промпт через stdin.** Почему: документированный путь для скриптов; stdin обходит лимит 32 KB командной строки Windows; `dontAsk` + явные разрешения вместо обхода прав. Не `--bare` — он не видит подписку, хуки и навыки. Из окружения процесса удаляются `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDECODE*`.
3. **Подтверждения — свой Guard-хук + Approvals API моста**, а не `--permission-prompt-tool` (схема не документирована) и не официальный Telegram-плагин channels (research preview, требует Bun, держит сессию открытой). Guard вызывается через абсолютный путь к `python.exe` из venv. Approvals API слушает только `127.0.0.1`, с одноразовым токеном из `state/secrets/`.
4. **Классификация действий** — таблица правил в `runtime/policy.yaml` (читает Guard; менять может только владелица): инструмент + шаблон аргументов → уровень. Неизвестный MCP-инструмент → EXTERNAL по умолчанию.
5. **Браузер — `@playwright/mcp` с `--user-data-dir state/browser-profile`, Edge/Chrome.** Почему: работает на Windows, держит логины, не требует своего LLM-ключа (в отличие от библиотеки browser-use). Один профиль = один браузер одновременно: браузерные задачи в очереди последовательно.
6. **Голос — faster-whisper, модель `small` int8 на CPU по умолчанию**, `medium` настраивается. Почему: бесплатно и локально; качество на русском проверяется на 5 реальных голосовых в сборке.
7. **Память и личность — файлы, импорт через `@` в `CLAUDE.md`.** Никакой БД в первой версии (R28).
8. **Навыки в `.claude/skills/`, агенты в `.claude/agents/`, черновики в `drafts/`.** Отступление от дерева брифа (там `skills/` в корне): Claude Code нативно подгружает навыки только из `.claude/skills/` — прогрессивная загрузка и живая перезагрузка работают без обвязки. Первый файл в новой `.claude/agents/` требует перезапуска — мост создаёт папку заранее.
9. **События** — `state/events.jsonl`, словарь: `user_message, assistant_message, tool_use, tool_result, approval_request, approval_decision, blocked, result{cost,duration}, error`, у каждого `ts, session, agent, task, status, progress` (как в брифе: `{"task": "reels-284", "agent": "reels-producer", "status": "working", "progress": 0.65}`). Почему: из этого же файла вырастет Control Room без переделки.
10. **Сессии** — `state/sessions.json`: `{chat_id: session_id}`.
11. **Условия подписки.** Личное использование немодифицированного `claude` своим логином документация не запрещает; лимиты рассчитаны на «обычное индивидуальное использование» — поэтому в мосте дневной бюджет запусков (настраиваемый) и никакого круглосуточного фонового «жжения». Клиентам — только своя подписка (см. G10).

| `claude_bridge` (runtime) | запуск Claude Code и разбор потока | `async run_turn(prompt, session_id|None, on_event) -> TurnResult{text, session_id, cost, status}`; `stop(run_id)` | флаги CLI, окружение, stdin, парсинг stream-json, retry resume, Windows-убийство дерева |

| `voice` | распознавание | `transcribe(path) -> text | None` | faster-whisper, ffmpeg |
| `events` | журнал событий | `emit(type, **fields)` → строка в `state/events.jsonl` | ротацию файла |
| `activation` | перенос черновиков | `list_drafts()`, `activate(kind, name)`, `discard(kind, name)` | проверку структуры SKILL.md/агента перед переносом |

**Швы для тестов:** (1) `claude_bridge.run_turn` с подменённым исполняемым файлом (фейковый `claude`, печатающий записанный stream-json) — через него проверяются сессии, очередь, статус, события; (2) `guard` — чистая функция «JSON вызова → решение», таблица тест-кейсов; (3) `approvals` HTTP — с фейковым gateway. Сквозной ручной тест — реальное сообщение из Telegram.

- `docs/ARCHITECTURE.md` — для владелицы и будущего разработчика: целевая архитектура, схема, модули и границы, потоки данных (6 потоков выше), модель безопасности (4 уровня, Guard, Approvals, секреты, изоляция, недоверенный контент), экономия контекста, что берём у каждого референса и что пишем сами, дорожная карта V0.1–V2.0 с DoD, риски (условия подписки, лимиты, Windows).
- `docs/MVP.md` — первая версия: что умеет (сценарии с телефона), что не умеет, структура каталогов, этапы V0.1a–V0.6-lite с DoD, что нужно от владелицы (токен бота, ID, профили, вход на сайты), как проверить готовность.
