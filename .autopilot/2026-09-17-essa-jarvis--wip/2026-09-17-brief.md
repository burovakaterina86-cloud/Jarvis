Что берём из уже найденных систем
МОЗГ — фундамент лёгкого runtime. Там мне нравится сама идея: маленький Python-мост вызывает Claude Code через CLI, сохраняет `session_id`, продолжает разговор через `--resume`, держит небольшую файловую память и не создаёт второй тяжёлый agent-runtime. Именно это нам нужно оставить. У МОЗГА Claude Code является настоящим «мозгом», а Python — только мостом.
claude-telegram-agent — главный архитектурный референс. Там уже есть почти все необходимые слои: Telegram → Claude Code, Playwright, Google Gmail/Drive/Calendar, файлы, shell, Telegram MTProto, голос, изображения и трёхуровневая память. Особенно ценны safety hooks: они блокируют опасные shell-команды и доступ к `.env`, ключам и credentials на уровне Claude Code, а не только промптом. ([GitHub](https://github.com/asqwaed/claude-telegram-agent?utm_source=chatgpt.com))
Threadwright — референс для управления компьютером и экономии контекста. Он умеет Telegram → Claude Code → Windows PC, Playwright и computer-use. Но целиком брать его тебе сейчас не стоит: текущая версия ориентируется на Windows 11 + .NET 10. Зато надо украсть архитектурную идею: `CLAUDE.md` остаётся коротким, а подробная документация лежит отдельно и читается только когда нужна. Автор прямо пишет, что это сделано для экономии контекста. ([GitHub](https://github.com/amusleh-spotware-com/threadwright?utm_source=chatgpt.com))
Claude-Agent — референс для будущей большой системы. У него уже выделены `.claude/agents`, `.claude/skills`, hooks, rules, Telegram/Discord, Web UI и desktop-приложение. Это хороший образец того, во что наш MVP может вырасти, но тащить весь этот слой в первую версию не надо. ([GitHub](https://github.com/claude-world/claude-agent?utm_source=chatgpt.com))
TrendRadar — новостной радар. Он агрегирует источники/RSS, умеет AI-фильтрацию по интересам, Telegram-пуши и MCP. В свежей версии уже оптимизирован повторный AI-анализ: ранее обработанные новости повторно не тратят токены. ([GitHub](https://github.com/sansan0/TrendRadar?utm_source=chatgpt.com))
Superpowers — методология работы. Это не «ещё один агент». Это набор skills, который заставляет coding-agent сначала понять задачу, спроектировать решение, составить план, выполнить его через субагентов и проверить результат. Его стоит использовать при разработке нашего JARVIS, а отдельные идеи перенести в его собственные skills. ([GitHub](https://github.com/skill-vault/obra-superpowers?utm_source=chatgpt.com))

Этап 1. MVP — Social Media JARVIS
Вот это я бы действительно строила первым.
Не пять агентов. Не Zoom. Не Dashboard.
Один главный агент:

```text
Telegram
   ↓
Claude Code
   ↓
ESSA / Умида workspace
   ↓
skills
   ↓
готовый контент
```

Что он должен уметь после первой версии:

```text
Ты:
"Работаем с ESSA.
Что сегодня публикуем?"

JARVIS:
→ определяет workspace
→ читает цели
→ смотрит последние материалы
→ использует trend/competitor research
→ выбирает тему
→ вызывает content-strategy
→ создаёт пост
→ создаёт Reels
→ создаёт Stories
→ сохраняет результат
→ возвращает всё в Telegram
```

И:

```text
"Переключись на Умиду.
Сделай контент на завтра."

→ открывает ТОЛЬКО workspaces/umida/
→ использует её VOICE/AUDIENCE/PRODUCT
→ готовит её контент
```

На этом этапе нужны 7 основных skills:
`trend-radar`, `competitor-research`, `content-strategy`, `content-plan`, `copywriting`, `reels-script`, `repurpose-content`.
Browser Use нужен уже здесь для исследования.
Автопубликация пока не нужна.
Сначала:
задача → результат → подтверждение человека.
Definition of Done MVP
Ты с телефона пишешь:
Сделай контент для ESSA на завтра.
И больше ничего руками не копируешь между ChatGPT, Claude, браузером и файлами.
Через Telegram получаешь готовый комплект.
Вот только тогда MVP закончен.
Этап 2. Память

Очень важный слой: безопасность
Вот здесь я бы не копировала МОЗГ буквально.
МОЗГ запускает Claude с:

```bash
--dangerously-skip-permissions
```

Это удобно, но для JARVIS с Gmail, браузером и компьютером слишком широкий доступ. Сам автор МОЗГА предупреждает, что в таком режиме Claude может выйти за пределы выбранной папки и что прочитанный внешний контент создаёт риск prompt injection.
У нас нужны четыре уровня:

```text
READ
→ автоматически

WRITE workspace
→ автоматически

EXTERNAL ACTION
отправить письмо
опубликовать пост
ответить человеку
→ approval policy

IRREVERSIBLE / MONEY
оплата
бронирование
удаление
покупка
→ обязательное подтверждение
```

А hooks из `claude-telegram-agent` я бы перенесла практически сразу. ([GitHub](https://github.com/asqwaed/claude-telegram-agent?utm_source=chatgpt.com))
Самое важное — как экономим Claude
Не надо превращать JARVIS в OpenClaw 2.
Всегда загружаются только:

```text
CLAUDE.md
SOUL.md
MEMORY.md
GOALS.md
```

Причём маленькие.
Например:

```text
CLAUDE.md     3–5 KB
SOUL.md       1–2 KB
MEMORY.md     3–5 KB
GOALS.md      1–2 KB
```

Skills — только когда подходят.
Knowledge — только когда нужен.
История — compress.
Подробные технические инструкции:

```text
docs/REFERENCE.md
```

а не `CLAUDE.md`.
Это как раз тот принцип, который Threadwright использует специально для экономии контекстных токенов. ([GitHub](https://github.com/amusleh-spotware-com/threadwright/blob/main/CLAUDE.md?utm_source=chatgpt.com))

И V1.0 я бы зафиксировала как первый настоящий продукт:
Личный автономный AI-контент-менеджер эксперта.
Он знает бизнес, клиента, ЦА, продукты и голос. Следит за трендами и конкурентами. Планирует контент. Делает посты, карусели, Stories и Reels-сценарии. Помнит опубликованное. Анализирует результаты. Работает через Telegram.
Это уже можно сначала прогнать на ESSA.AI и Умиде, а потом превращать в клиентский продукт.
С чего начать в Claude Code
Не надо первым промптом просить:
«Сделай мне автономного Джарвиса».
Он попытается построить пол-Интернета.
Первый запрос я бы дала ему такой:
Создаём проект `ESSA-JARVIS`.
Это лёгкий автономный персональный агент поверх Claude Code. Claude Code является единственным основным агентным runtime. Мы НЕ создаём второй LLM-orchestrator и не используем OpenClaw.
Архитектурные референсы:

* MikhailDergachev/mozg — лёгкий Python bridge к Claude Code, session resume, Windows-first запуск;
* asqwaed/claude-telegram-agent — Telegram, Playwright, Google Workspace, persistent memory, safety hooks;
* amusleh-spotware-com/threadwright — session routing, Windows computer-use и progressive disclosure документации;
* claude-world/claude-agent — skills, agents, rules, hooks и дальнейший Web UI;
* sansan0/TrendRadar — trend monitoring;
* Superpowers — дисциплинированная skill-based разработка.

Первый продукт — Social Media Agent для двух независимых workspaces: `essa-ai` и `umida`.
Сейчас НЕ реализовывай весь проект.
Сначала:

1. изучи перечисленные репозитории;
2. создай `docs/ARCHITECTURE.md`;
3. создай `docs/MVP.md`;
4. предложи структуру каталогов;
5. опиши потоки данных и модель безопасности;
6. раздели разработку на маленькие этапы с проверяемым Definition of Done;
7. отдельно опиши, что мы переиспользуем как архитектурный паттерн из каждого проекта, а что писать сами.

Ограничения:

* Windows 10;
* Python как основной bridge/runtime;
* Claude Code через существующую подписку;
* Telegram — основной интерфейс;
* минимальный расход контекста;
* никаких `--dangerously-skip-permissions` глобально;
* клиентские данные строго изолированы;
* необратимые внешние действия требуют подтверждения;
* никакой сложной БД и dashboard в MVP;
* skills и knowledge загружаются только по необходимости.

После архитектуры остановись. Код не пиши, пока я не подтвержу дизайн.
