# 03 — Approvals API: подтверждения владелицы

**Требования:** R14, R26
**Blocked by:** 01
**Зона:** `runtime/approvals.py` · `tests/test_approvals.py`
**Волна:** 2
**Status:** ready

## Что должно заработать

Локальный HTTP-сервис (aiohttp, `127.0.0.1`, порт из `state/approvals.port`, токен из `state/secrets/approvals.token`, создаются при старте), через который Guard спрашивает владелицу. `POST /approve` с заголовком токена и телом `{level, tool, summary, details}` держит соединение, пока не придёт решение или таймаут 10 мин. Решение приходит через `resolve(request_id, decision)` — его вызовет Telegram-слой (таск 04) по нажатию кнопки; до этого `approvals` сообщает о новом запросе через подписку `on_request(callback)`. Каждый запрос и решение → `state/approvals.jsonl` и событие `approval_request`/`approval_decision`. Запрос без токена → 401. Параллельные запросы независимы.

## Из брифа, дословно

> «EXTERNAL ACTION отправить письмо опубликовать пост ответить человеку → approval policy»
> «задача → результат → подтверждение человека»

## Критерии приёмки

- [ ] `POST /approve` с верным токеном и последующим `resolve(allow)` → `{decision: allow}`; с `resolve(deny)` → deny
- [ ] Без ответа до таймаута (в тесте — 1 с через параметр) → deny с причиной `timeout`
- [ ] Без токена или с чужим → 401, `on_request` не вызывается
- [ ] Слушает только 127.0.0.1 (тест проверяет адрес привязки)
- [ ] Журнал `approvals.jsonl` содержит запрос и решение
- [ ] Интеграционный тест: реальный `guard.py` из таска 01 + поднятый API + авто-resolve → exit 0 / exit 2
