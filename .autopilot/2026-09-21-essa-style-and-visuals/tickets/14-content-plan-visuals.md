# Таск 14 — картинки доезжают до основного сценария; починить проверку хуков

Требования: B05, B06.

Зона: `.claude/skills/content-plan/SKILL.md`, `scripts/check_hooks.py`, `requirements.txt`, `docs/SETUP.md`, `.agents/skills/`, тесты рядом с ними
(`tests/test_skills_format.py` не ломать; новые проверки — в отдельном файле `tests/test_content_plan_visuals.py`).
**Не трогай** `integrations/visuals/`, `.claude/skills/carousel-instagram/`, `tests/test_visuals.py` — там
параллельно идёт другой таск.

## 1. content-plan вызывает вёрстку (B05)

Основной сценарий владелицы — сообщение с телефона «сделай контент на завтра» — идёт через навык
`content-plan`. Он собирает тексты (пост, карусель, Reels, Stories), но **картинок не делает**:
навык `carousel-instagram` и команда сборки `python -m integrations.visuals.build` в нём не упоминаются.
Её слова из брифа: «не делает, ни карусели, ни фоны для сторис, ни обложки для постов». Для отдельной
команды это исправлено, для основного сценария — нет.

- В цепочку `content-plan` после готового текста карусели добавить шаг оформления: вызвать навык
  `carousel-instagram` (storyboard → `slides.json` → сборка одной командой) и положить PNG в папку
  комплекта. Обложка поста и фон сторис — тем же навыком.
- Код выхода сборки не 0 — владелице сказать прямо, что картинок нет и почему; тексты комплекта
  при этом всё равно отдаются. Формулировки кодов — в `carousel-instagram/SKILL.md`, не дублируй, сошлись.
- В ответе в Telegram — что картинки лежат в папке комплекта.
- Ничего не публикуется — это правило навыка остаётся.

## 2. Проверка хуков берёт не тот bash (B06)

`.venv\Scripts\python.exe scripts\check_hooks.py` → `ИТОГ: расхождений: 5`, код 1,
`/bin/bash: line 1: /.venv/Scripts/python.exe: No such file or directory`. Скрипт подхватил bash из
`C:\WINDOWS\system32` (это WSL), где путь `.venv\Scripts\python.exe` не существует.

- Найди причину одной строкой и почини так, чтобы скрипт исполнял команды хуков тем же способом,
  каким их исполняет Claude Code на этой машине (Git Bash), или явно отказывался с понятной
  причиной, если подходящего bash нет.
- Не ослабляй проверки скрипта и не убирай случаи.
- Добавь в него случай на заслон больших файлов (сейчас ни одного нет): чтение файла >100 КБ
  целиком → просит подтверждения, кусок → проходит. **Проверяй через `decide`, а не через запуск
  `guard.py` целиком**: ответ «ask» у живого хука отправит владелице запрос в Telegram.

## 3. `playwright` в `requirements.txt`

Пакет стоит в `.venv`, но в `requirements.txt` его нет: на чистой установке рендер не заработает.
Добавь с версией, которая стоит сейчас (`.venv\Scripts\python.exe -m pip show playwright`).
В `docs/SETUP.md` одной строкой: после установки зависимостей — `python -m playwright install chromium`.

## 4. Зеркало навыков `.agents/skills/`

`AGENTS.md`: «`.agents/skills/` … зеркала навыков … для других CLI; правишь `.claude/` — синхронизируй их».
Десять новых папок в зеркале есть, но git их не отслеживает, а `carousel-instagram` в зеркале уже устарел.
**Синхронизацию делай в самом конце**, после того как параллельный таск по вёрстке закончит
`carousel-instagram/SKILL.md` — иначе зеркало устареет снова. Если к концу твоей работы тот таск ещё
идёт, синхронизацию `carousel-instagram` пропусти и скажи об этом в CONCERNS. Остальные девять
синхронизируй. Лучше добавь простую проверку-тест: каждый навык из `.claude/skills/` совпадает со
своим зеркалом — тогда устаревание будет краснеть само.

## Критерии готовности

- В `content-plan` есть шаг оформления картинок; тест проверяет, что навык ссылается на
  `carousel-instagram` и на команду сборки, и что при ненулевом коде тексты всё равно отдаются.
- `scripts\check_hooks.py` на этой машине выходит с 0 и без расхождений, либо честно отказывается
  с причиной — но не падает на пути к Python.
- Полный прогон зелёный.
